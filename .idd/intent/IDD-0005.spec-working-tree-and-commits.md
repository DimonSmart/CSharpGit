# IDD-0005.spec-working-tree-and-commits

## Intent

Пользователь явно управляет working tree и Git index на уровне целых файлов,
создает commit только из фактически staged изменений и получает защищенный от
случайной потери данных workflow.

## Behavior

- UI показывает modified, added, untracked, deleted, renamed и conflicted files.
- Staged и unstaged — независимые характеристики относительно разных Git states:
  один файл может одновременно иметь staged и дополнительные unstaged changes,
  и UI однозначно это показывает.
- Working-tree и staged списки поддерживают стандартный desktop multi-selection.
  Пользователь может явно stage/unstage один или несколько выбранных файлов,
  а также выполнить Stage all и Unstage all.
- Batch operations сохраняют реальную Git index semantics: staged и unstaged части
  одного физического файла остаются независимыми, а один файл может одновременно
  присутствовать в staged и unstaged представлениях.
- Working Tree diff остается single-file view для последнего активированного
  элемента и не превращается в aggregate diff выбранного набора.
- Обычный Commit создает commit из текущего Git index и не выполняет неявный
  stage или unstage; дополнительные unstaged changes в commit не попадают.
- Если Commit инициирован при пустом index, но непустом working tree, модальный
  confirmation явно предлагает: `Stage all and commit`, `Create empty commit` либо
  `Cancel`. Никакой stage не выполняется до явного выбора пользователя.
- Intentional empty commit допустим только как явно отдельное осознанное действие.
- После успешного commit обновляются history, graph, refs, working tree и index.
- Amend last commit доступен как явно обозначенный режим и сохраняет реальную Git
  semantics.
- В Unstaged changes пользователь может выполнить `Discard selected` для одного или
  нескольких выбранных eligible items либо `Discard all…` для всех eligible unstaged
  items, отображаемых Working Tree на момент открытия confirmation.
- Для tracked paths Discard изменяет только Working Tree и восстанавливает его из
  Git index, а не из HEAD. Поэтому staged version того же файла сохраняется даже при
  одновременных staged + unstaged changes и операция работает в unborn repository,
  если path уже присутствует в index.
- Для untracked file Discard означает физическое удаление только явно подтвержденного
  файла. Ignored files не затрагиваются, `git clean` не используется, а untracked
  directory не удаляется рекурсивно неявно.
- Любой Discard требует explicit modal `ContentDialog`. Confirmation показывает
  количество affected files и отдельно предупреждает о permanently deleted untracked
  files, если они входят в snapshot. Без подтверждения mutation не выполняется.
- Подтвержденный Discard работает ровно по snapshot, показанному пользователю:
  изменения, появившиеся после открытия confirmation, не включаются автоматически.
- Discard выполняется best effort по каждому item. Успешно обработанные paths не
  откатываются при ошибках других paths; failed paths и причина ошибки показываются
  пользователю, после чего Working Tree перечитывается из authoritative Git state.
- Unresolved/conflict paths не являются eligible для обычного Discard. Если selection
  содержит одновременно обычные и conflict items, `Discard selected` disabled;
  conflict resolution остается только в workflow IDD-0008.
- При закрытии репозитория или приложения непустой, еще не примененный commit
  message не теряется молча; используется confirmation, draft или иной простой и
  понятный механизм.
- Explicit confirmations destructive/potentially destructive desktop actions используют
  стандартный WinUI/Uno `ContentDialog` с безопасным `Cancel`/`Close`/`Keep editing`
  как default action. Status, informational states, errors и persistent operation UI
  могут оставаться inline и не превращаются в modal confirmation.
- Unresolved conflicts разрешаются только через conflict workflow из IDD-0008;
  обычные bulk staging actions не используются как неявный способ отметить их
  resolved или разрушить conflict index state.

## Durable Architecture And Constraints

- Index остается реальным Git index, а staging — самостоятельной пользовательской
  операцией.
- После staging mutation UI не переносит WorkingTreeChange между собственными
  collections, а перечитывает authoritative repository/index state и перестраивает
  presentation collections из фактического состояния Git.
- Batch stage/unstage одного набора файлов выполняется одной Git pathspec operation,
  а не N отдельными Git processes; один batch mutation сопровождается одним
  repository refresh на presentation/application уровне.
- Batch selection и active single-file diff selection являются разными состояниями.
  Selection staged и unstaged списков независим, тогда как active diff всегда
  относится ровно к одному элементу одного списка.
- Discard tracked path семантически эквивалентен restore Working Tree from index,
  например `git restore --worktree -- <path>`: он не использует HEAD как источник и
  никогда не выполняет `--staged`/reset index.
- Batch discard может выполнять отдельные filesystem/Git operations для сохранения
  независимого success/failure результата каждого item, но presentation refresh
  выполняется после завершения всего подтвержденного snapshot.
- `Discard all…` получает immutable snapshot eligible unstaged items до confirmation;
  confirm не перечитывает и не расширяет этот набор новыми paths.
- Иные действия не меняют index молча, кроме неизбежной стандартной части явно
  показанной Git operation.
- Destructive operations не получают фиктивную модель Undo, если Git не
  предоставляет безопасного Undo.
- Риск потери данных обозначается явно и требует осознанного действия.

## Non-Goals

- Hunk, line или иное partial staging в MVP.
- Partial discard отдельных hunks или lines.
- Discard staged changes или reset index.
- Aggregate diff для multi-selection.
- Cleanup ignored files, `git clean -fdx` и аналоги.
- Неявное рекурсивное удаление untracked directories, представленных одним item.
- Изменение существующего conflict-resolution workflow.
- Сложная persistent session model только ради сохранения commit message.
- Неявное включение unstaged файлов в обычный commit.
- Custom staging model, отдельная от реального Git index.

## Acceptance Criteria

- Пользователь различает staged и unstaged части одного файла и может stage или
  unstage целый файл.
- Unstaged и Staged lists поддерживают desktop multi-selection: обычный click,
  Ctrl+click для произвольного набора и Shift+click для диапазона там, где это
  поддерживается desktop Uno/WinUI target.
- Stage selected и Unstage selected работают со snapshot текущего selection и
  передают весь набор одной Git operation.
- Stage all и Unstage all не зависят от selection. Unstage никогда не изменяет
  working-tree content, включая initial/unborn repository.
- Modified, added/untracked, deleted, renamed, paths со spaces/Unicode и файл с
  одновременными staged/unstaged changes сохраняют Git semantics.
- Для rename batch pathspec учитывает и current Path, и OriginalPath.
- После explicit Stage/Unstage обе batch selections, active Working Tree item и
  diff очищаются; passive refresh может сохранить active preview по path.
- Быстрый повторный запуск mutation не приводит к queued operation со stale
  selection после первого refresh.
- `Discard selected` доступен при непустом selection только если все выбранные items
  eligible; mixed normal + conflict selection его отключает.
- `Discard all…` доступен при наличии хотя бы одного eligible unstaged item и не
  зависит от текущего selection.
- Оба discard actions требуют modal `ContentDialog`. Confirmed snapshot не расширяется
  изменениями, появившимися позже; Cancel не выполняет mutation.
- После Discard tracked Working Tree content соответствует index, untracked files из
  snapshot удалены, а staged/index state остается идентичным состоянию до Discard.
- Partial failure оставляет успешно обработанные items обработанными, показывает
  failed paths и после завершения обновляет Working Tree.
- Conflict paths никогда не проходят через обычный Discard workflow.
- Bulk staging actions не обходят unresolved conflict workflow IDD-0008.
- Commit включает ровно текущее содержимое index.
- Commit при пустом index не выполняет silent staging и дает modal choice между
  `Stage all and commit`, `Create empty commit` и `Cancel`.
- Amend визуально не смешивается с обычным commit.
- Непустой commit message не теряется молча при закрытии.
- Destructive confirmations не используют inline `InfoBar`; safe action является
  default. Persistent operation/status/info/error UI остается inline там, где это
  соответствует его назначению.

## Verification

- Git integration tests проверяют StageFilesAsync, UnstageFilesAsync и
  UnstageAllAsync на реальных временных repositories.
- Проверяются batch combinations modified, added/untracked, deleted и renamed,
  subset unstage, spaces/Unicode paths и OriginalPath.
- Отдельно проверяется файл `HEAD=A, index=B, working tree=C`: stage из unstaged
  дает index=C, а unstage из staged возвращает index к HEAD, сохраняя working tree=C.
- Обязательный unborn regression: после `git add` версии A и последующего изменения
  working tree до B UnstageFilesAsync удаляет файл из index, оставляет B byte-for-byte
  и показывает файл как untracked. UnstageAllAsync аналогично очищает весь index,
  не удаляя working-tree files.
- Discard integration tests проверяют modified/deleted tracked files, multiple
  selection, untracked deletion, mixed tracked + untracked, `Discard all…`, spaces,
  Unicode и modeled rename.
- Отдельные discard regressions проверяют `HEAD=A, index=B, working tree=C`, несколько
  staged+unstaged files и unborn repository: working tree после Discard равен index,
  а staged diff/index byte-for-byte/semantically остается прежним.
- Snapshot regression создает новый unstaged/untracked path после открытия
  `Discard all…` confirmation и проверяет, что новый path не обрабатывается.
- Best-effort tests проверяют, что failure одного restore/delete не отменяет успешные
  items, failure report содержит path, а untracked directory не удаляется рекурсивно.
- UI contract/selection tests проверяют Stage selected, Stage all, Unstage selected,
  Unstage all, `Discard selected`, `Discard all…`, `SelectionMode="Extended"`,
  modal destructive confirmation, safe default action, conflict eligibility,
  независимость selections и single-file active preview.
- Проверяются success и failure outcomes staging, commit и discard, последующее
  соответствие UI реальному репозиторию и защита введенного commit message.

## Selected-file Working Tree diff

- Working Tree keeps staged and unstaged deltas as two distinct user-visible states.
- Selecting an unstaged row reads and shows only `index -> working tree`; selecting a staged row reads and shows only `HEAD -> index`.
- A file that has both staged and additional unstaged edits may appear in both lists and produces two different diffs.
- Multi-selection does not create an aggregate diff. Preview follows the last explicitly selected/activated item while batch selections remain independent between lists.
- Diff loading is lazy (selection only), cancellable, and guarded against stale completion after selection or repository state changes.
- Added, deleted, renamed, untracked, binary, Unicode/space paths, and unborn-HEAD staged changes retain Git semantics. Unmerged entries defer to the conflict workflow rather than presenting an incorrect two-way diff.
- `Discard selected` and `Discard all…` operate only on the Unstaged side: tracked paths are restored from index, untracked files are deleted only from the confirmed snapshot, staged content remains unchanged, and conflicts stay in their dedicated workflow.
