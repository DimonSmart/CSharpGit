# IDD-0015.adr-win32-vulkan-rendering

## Status

Accepted

## Context

На Windows в Skia Desktop при использовании стандартного Win32 rendering backend
наблюдались визуальные артефакты при изменении размера окна: фон выбранной строки
истории коммитов частично перерисовывался некорректно и оставлял диагональные /
ступенчатые области старого изображения.

Обновление Uno SDK с 6.5.36 до 6.7.22 проблему не устранило.

Диагностические проверки показали:

- стандартный Win32 backend воспроизводит проблему;
- явный `Win32RenderingBackend.Software` проблему устраняет;
- явный `Win32RenderingBackend.Vulkan` также проблему устраняет.

Это локализует проблему в rendering path стандартного Win32 backend, а не в
`ListView`, `ListViewItem`, commit graph control или логике resize приложения.
Нужно сохранить аппаратное ускорение и при этом избежать известного артефакта.

## Decision

- На Windows явно использовать `Win32RenderingBackend.Vulkan` для Skia Desktop.
- Не менять rendering backend для macOS, X11 и Linux framebuffer в рамках этого
  решения.
- Не вводить custom `ListViewItem` template или дополнительную invalidate/redraw
  логику как workaround этой проблемы.
- Считать явный Vulkan backend платформенным rendering decision, а не частью
  продуктовой UI-логики.
- Периодически пересматривать решение после обновлений Uno/Skia; если стандартный
  Win32 backend будет подтвержденно работать без resize repaint artifacts, явную
  настройку Vulkan можно удалить.

## Alternatives Considered

- Оставить стандартный Win32 backend — отклонено, потому что визуальный артефакт
  стабильно воспроизводится при resize.
- Использовать `Win32RenderingBackend.Software` — подтверждено как рабочий
  workaround, но отклонено как основной вариант из-за отказа от GPU acceleration.
- Переписать selection visual `ListViewItem` — отклонено: тот же UI корректно
  работает при Software и Vulkan backend, поэтому изменение control template не
  устраняет первопричину и добавляет лишнюю UI-сложность.
- Добавить принудительные `InvalidateArrange` / redraw вызовы после resize —
  отклонено как маскировка rendering defect и потенциальный источник лишних
  перерисовок.

## Consequences

- Windows использует Vulkan как явный GPU rendering backend.
- Исправляется наблюдавшийся resize repaint artifact без перехода на CPU-only
  rendering.
- На системах с ограниченной или проблемной Vulkan-поддержкой поведение зависит
  от fallback-механизма Uno/Skia; такие системы требуют отдельной проверки.
- Причина выбора backend задокументирована рядом с durable architecture intent,
  поэтому настройку нельзя считать случайной оптимизацией и удалять без проверки
  исходного resize scenario.

## Future Options Preserved

- Вернуться к стандартному Win32 backend после подтвержденного upstream fix.
- Использовать Software backend как диагностический или аварийный fallback, если
  конкретная система имеет проблемы с Vulkan.
- Подготовить минимальный reproduction для Uno/Skia и отслеживать upstream fix
  отдельно от прикладного UI-кода.
