# External Git Tools and Git Tools Settings

## Intent

CSharpGit supports the user's standard Git Editor, GUI Diff Tool, and GUI Merge Tool without maintaining a parallel CSharpGit-specific source of truth. Settings exposes these values as `Settings → Git Tools` and acts as a viewer/editor for Git configuration and environment precedence.

This specification extends the file-version and conflict workflows in IDD-0017 and IDD-0008. The earlier IDD-0017 statement that preferred-editor settings are out of scope no longer applies: explicit edit actions use the effective Git Editor defined here. Shell reveal/open-with-default remains a separate desktop capability.

## Configuration source of truth

- Editor uses `GIT_EDITOR → core.editor → VISUAL → EDITOR → Git default`.
- GUI Diff uses Git GUI semantics, including `diff.guitool → merge.guitool → diff.tool → merge.tool` and Git-supported `difftool.<tool>.*` fallback to `mergetool.<tool>.*` for tool path/command configuration.
- GUI Merge uses `merge.guitool → merge.tool` and `mergetool.<tool>.*`.
- Diff uses the standard non-tool-specific `difftool.trustExitCode`; Merge uses `mergetool.<tool>.trustExitCode`. Merge also exposes `mergetool.keepBackup`.
- Effective values show source and config origin. Environment/command, worktree, repository/local, global, system, includes, and Git defaults are recognized.
- Writable scopes are Global and This repository. Worktree/system/environment values are visible but are not silently rewritten.
- Presets are presentation only. No selected preset, effective tool, resolved executable, or other derived duplicate is stored in application settings.
- Existing generic keys (`diff.tool`, `merge.tool`) remain valid and are not migrated merely by opening Settings. New GUI selections prefer `diff.guitool` / `merge.guitool`.
- Opening/closing Settings, detection, and suggestions perform no writes. Save writes only changed standard Git keys. Remove override removes only the active writable selection key and does not clean unrelated or inactive tool configuration.
- CSharpGit never changes `difftool.prompt` or `mergetool.prompt` for its UX; launches use `--no-prompt`.

## Git Tools Settings UX

The page has Editor, Diff Tool, and Merge Tool sections. Each shows:

- effective value, source, and origin;
- Global, Repository, Worktree, and System values as separate rows when applicable;
- selected writable scope;
- known/detected preset or Custom;
- explicit path, custom command, resolved executable, and validation where applicable;
- warning text when a higher-priority scope means a saved lower-scope value will not become effective;
- Save, Remove override, and isolated Test action.

Environment/command overrides are shown through the effective Source/Origin rather than exposed as editable configuration. System and Worktree are read-only in this settings surface.

Known presets include common cross-platform tools such as VS Code, Meld, KDiff3, Beyond Compare, P4Merge, Araxis, plus platform-specific tools such as WinMerge / Visual Studio on Windows and `opendiff` on macOS. Git's `difftool --tool-help` and `mergetool --tool-help` augment the list. Unknown configured tools remain usable as Custom.

Explicit invalid executable paths are errors. Unresolved bare PATH commands are warnings and do not prevent saving otherwise valid Git configuration. Diff custom commands require `$LOCAL` and `$REMOTE`; Merge custom commands require `$LOCAL`, `$REMOTE`, `$MERGED`, while `$BASE` is optional. Raw Git command values are passed through Git rather than parsed/requoted by Presentation.

## External diff semantics

`Open in Diff Tool` is available from file context menus and compact file/diff actions. It consumes the same resolved `DiffFileVersionPair` as built-in Original/Changed actions; Presentation must not derive another baseline.

Consequently:

- Unstaged compares Index ↔ Working Tree.
- Staged compares HEAD ↔ Index, independently from an unstaged row for the same file.
- Commit files use the displayed commit diff baseline, including first-parent/current display semantics, merge commits, and root commits.
- Added/deleted/untracked sides use an empty side where one side is absent.
- Rename/copy use the resolver's old/new paths.
- Binary regular files are allowed.
- Unsupported entry types such as gitlinks/symlink snapshots remain unavailable according to the file-version infrastructure.

CSharpGit launches standard Git difftool integration with GUI/no-prompt semantics. Once the pair is already resolved, `git difftool --no-index` may be used to materialize that exact pair rather than reconstructing revision semantics independently.

If no effective Diff Tool exists, the action explains that it is not configured and offers navigation directly to `Settings → Git Tools`.

## Merge and editor workflows

Existing selected-conflict `Open in Merge Tool` and repository-level `Start Merge Tool` remain distinct and both use the centralized Git Tools configuration. They launch `git mergetool --gui --no-prompt`. Completion is followed by normal repository refresh; only actual Git index/working-tree state determines resolvedness, regardless of process exit or `trustExitCode` behavior.

Explicit `Edit in external editor` actions, including manual conflict editing, use the effective Git Editor. Reveal in Explorer/Finder and open-with-system-default remain separate shell operations and never synthesize `core.editor`.

## Test actions

- Editor test opens a temporary text file with the effective Git Editor.
- Diff test compares two temporary files through real `git difftool` integration without modifying the current repository.
- Merge test creates an isolated temporary repository and artificial conflict, then invokes the effective `git mergetool`; it does not modify the current repository or persistent user Git config.

## Architecture

Presentation binds only to application-level Git Tools capabilities. Git CLI configuration/execution, PATH lookup, shell/process launch, and platform handling remain behind Git/Infrastructure boundaries.

Diff and Merge share one configuration/preset/validation model. External diff accepts the authoritative resolved file pair from `IRepositoryFileVersionService`. No effective configuration is persisted as independently stored derived state.

Windows and macOS are first-class: paths with spaces/Unicode, PATH commands, executable paths, quoted command arguments, and platform-specific presets must remain valid.

## Verification

Automated coverage includes configuration precedence and removal, includes/origin, system and environment sources, GUI/generic fallback, unknown/custom commands and quoting, no-op saves, validation, exact staged/unstaged/added/deleted/root/rename/copy/binary diff pairs, empty-side external diff, selected-file and repository-level merge workflows, actual Git conflict-state refresh, isolated Editor/Diff/Merge tests, launch diagnostics, and platform-specific command/path construction on the CI operating-system matrix.

Ordinary CI must not launch real GUI tools. A manual smoke test with at least one common real tool on Windows and one on macOS remains a release/development verification step rather than an automated CI action.
