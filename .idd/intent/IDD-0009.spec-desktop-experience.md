# IDD-0009.spec-desktop-experience

## Intent

Главное окно объединяет основные Git-сценарии в отзывчивом, диагностируемом и
предсказуемом desktop UI, который остается usable на реальных больших
репозиториях и безопасно координирует конкурентные операции.

## Behavior

- Главное окно дает быстрый доступ к history, graph, branches/refs, staged и
  unstaged working tree changes, commit details, diff и основным Git actions.
- Пользователь изменяет размеры основных панелей, когда это нужно для комфортной
  работы.
- Appearance поддерживает System, Light и Dark с Fluent design; pixel-perfect
  одинаковый вид на разных ОС не требуется.
- При открытом repository нативный заголовок главного окна показывает имя
  фактически открытого repository/worktree и текущую branch либо detached HEAD
  identity, чтобы окно можно было однозначно идентифицировать в системном window
  switcher, taskbar или dock. Без открытого repository title равен `CSharpGit`.
- Стартовый список recent repositories показывает существующие локальные пути
  раньше недоступных, сохраняя порядок последнего открытия внутри каждой группы.
- Недоступная recent repository остается видимой до явного удаления. Пользователь
  может удалить такую запись отдельно или одним действием удалить все записи,
  чьи директории больше не существуют; существующие записи при bulk cleanup не
  затрагиваются.
- Долгие Git и filesystem operations, а также загрузка истории не блокируют UI.
  Заметная операция показывает busy state.
- Повторное действие не запускает случайно несколько одинаковых или
  конфликтующих operations.
- В одном репозитории несовместимые mutating operations не выполняются
  параллельно: actions отключаются либо попытка корректно отклоняется. Безопасные
  read-only operations могут выполняться параллельно.
- Git errors показываются понятным кратким описанием и контекстом, при
  необходимости сохраняя доступ к исходной диагностике Git; необработанный stack
  trace не является единственным пользовательским сообщением.

## Durable Architecture And Constraints

- UI остается отзывчивым на реальных репозиториях с большой историей, diff и
  внешними filesystem changes.
- Данные загружаются по потребности; история всегда поддерживает incremental
  loading.
- Presentation, application/domain, Git integration и platform infrastructure
  разделены согласно IDD-0002.
- `OpenRepositoryViewModel` является repository lifecycle/composition owner, а
  крупные Git-specific presentation workflows имеют отдельный ownership:
  `InteractiveRebaseViewModel` подготавливает/редактирует/запускает interactive
  rebase, а `RepositoryOperationsViewModel` владеет уже активной repository
  operation, merge state, conflicts, resolution и Continue/Abort/Skip.
- Feature ViewModels не зависят друг от друга напрямую; координация перехода от
  подготовленного interactive rebase к active operation выполняется через узкие
  repository contexts и authoritative repository refresh.
- Ошибки не скрываются искусственно, а технической информации достаточно для
  troubleshooting.

## Non-Goals

- Предварительная загрузка всех потенциально доступных данных.
- Автоматическое удаление recent repository только потому, что ее директория
  временно недоступна.
- Параллельный запуск несовместимых mutating Git operations.
- Pixel-perfect одинаковый интерфейс на разных ОС.
- Маскировка Git errors общим сообщением без полезной диагностики.

## Acceptance Criteria

- Все основные области доступны из главного окна, а ключевые панели можно
  комфортно изменять по размеру.
- System, Light и Dark применяются согласованно.
- Без repository title содержит только `CSharpGit`; с repository title начинается
  с имени фактически открытого repository/worktree и актуальной HEAD identity.
  Переходы между branch и detached HEAD отражаются без перезапуска окна, а
  presentation title не запускает дополнительные Git operations.
- В recent repositories существующие директории идут раньше отсутствующих, а
  внутри обеих групп сохраняется recent ordering.
- Bulk cleanup удаляет только записи с отсутствующими директориями и оставляет
  доступные recent repositories без изменений.
- Долгие операции оставляют UI интерактивным и имеют понятное состояние занятости.
- Конфликтующие повторные operations не запускаются одновременно.
- Ошибки Git и внешних tools понятны пользователю и пригодны для troubleshooting.
- Внешний change не оставляет UI надолго в заведомо устаревшем состоянии.

## Verification

- В запущенном приложении проверяются layout, resizing, scrolling, clipping,
  themes, реальные данные и enabled/disabled states.
- Нативный title проверяется при старте без repository, открытии repository,
  смене branch, detached HEAD, возврате на branch и переключении repository.
- На стартовом экране проверяются mixed available/missing recent repositories,
  их порядок и bulk cleanup без удаления существующих записей.
- На большом тестовом репозитории проверяются первый полезный render,
  incremental loading, diff, refresh и отсутствие блокировки UI.
- Проверяются повторные команды, несовместимые mutating operations и безопасные
  concurrent read-only operations.
- Для Git и external-tool failures проверяются краткое сообщение, контекст и
  доступность исходной диагностики.
