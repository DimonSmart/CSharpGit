# IDD-0034.adr-machine-readable-git-output-presentation-boundary

## Status

Accepted

## Context

CSharpGit intentionally uses machine-readable Git interfaces such as `git status -z`,
`git ls-files -z`, `git for-each-ref --format=...%00...` and
`git reflog --format=...%x00...`. These formats use NUL and other control
characters as delimiters. They are valid application data but are not guaranteed
to be safe input for general-purpose desktop text controls.

A reproduced Git Console case uses:

```text
git for-each-ref --format=%(refname)%00%(objectname)%00...
```

Git interprets `%00` in the format and emits literal `U+0000` characters. The
captured stdout can therefore contain machine-readable delimiters that must remain
available to Git/Application parsing while still being rendered safely in Uno/Skia
`TextBox` controls.

The existing capture semantics are already textual rather than byte-for-byte: Git
stdout/stderr are UTF-8 decoded, result output has its existing CR/LF trimming, Git
Console history has a bounded UTF-8 buffer and truncation marker, and binary
streamed-to-file output follows a separate path. This ADR does not change those
rules.

## Decision

Establish an explicit presentation boundary:

```text
Git / Application
    captured machine-readable text
            ↓
Presentation boundary
    encode UI-unsafe controls
            ↓
XAML / user-facing text surfaces
```

- Git execution, history, services and machine-readable parsers do not perform
  UI-specific escaping.
- Presentation does not pass machine-readable control delimiters directly to
  general-purpose XAML text controls.
- Git Console retains its existing carriage-return progress-line semantics.
- Newline (`\n`) remains a newline and tab (`\t`) remains a tab.
- NUL (`U+0000`) is shown as the two printable characters `\0`.
- Other `char.IsControl` characters are encoded deterministically as uppercase
  `\xNN` when the code unit is at most `U+00FF`, otherwise as `\uXXXX`.
- Printable Unicode characters are not escaped.
- `Copy all` applies the same unsafe-control escaping to stdout/stderr while
  preserving real `\r`, `\n` and `\t` characters.
- Machine-readable command formats such as `%00`, `%x00` and `-z` remain
  unchanged.

## Alternatives Considered

**Remove or replace NUL in `GitCommandExecutor`.** Rejected because Presentation
concerns would alter Git/Application captured semantics and could break parsers.

**Replace `%00`, `%x00` or `-z` with newline-delimited commands.** Rejected because
NUL-delimited output is an intentional Git machine-readable interface.

**Patch only `for-each-ref`.** Rejected because the issue applies to the general
class of machine-readable Git output.

**Patch only ListView selection/template behavior.** Rejected because unsafe
diagnostic data would still reach text controls even if a framework-level
selection artifact were independently fixed.

## Consequences

- Git/Application capture semantics and parser inputs remain unchanged.
- Git Console displays machine-readable delimiters visibly and deterministically.
- Streaming and full reset/resync share the same presentation-safe representation.
- Clipboard text no longer contains literal NUL or equivalent unsafe delimiters.
- Future Presentation surfaces that show captured Git diagnostics as ordinary text
  must apply the same boundary policy.

## Supersedes

None.
