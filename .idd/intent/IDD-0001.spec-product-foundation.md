# IDD-0001.spec-product-foundation

## Intent

Продукт — современный кроссплатформенный desktop GUI-клиент для Git,
ориентированный на повседневные сценарии работы с локальными репозиториями и
сохраняющий реальную Git semantics.

Git Extensions служит behavioral reference для сценариев, которые явно не
определены текущими intent-документами. Приоритет имеют явно записанные
требования, затем фактическая Git semantics, затем поведение Git Extensions.
Существенные отступления от этого reference должны быть осознанными продуктовыми
решениями.

## Behavior

- Основные поддерживаемые платформы — Windows и macOS. Linux поддерживается в
  режиме best effort.
- Один экземпляр приложения работает с одним открытым репозиторием.
- Пользователь может запустить несколько экземпляров для разных репозиториев или
  для наблюдения за одним репозиторием; централизованная блокировка экземпляров
  не требуется.
- Основной MVP-сценарий начинается с выбора существующей локальной папки и
  открытия находящегося в ней Git-репозитория или Git worktree.
- Приложение имеет одну общую продуктовую модель и основную иерархию интерфейса
  на всех платформах. Платформенные различия допустимы для интеграции с ОС.
- UI первой версии использует английский язык.

## Durable Architecture And Constraints

- Продукт остается desktop-first приложением с общей кроссплатформенной UI-базой.
- Платформенный код ограничивается возможностями, которым действительно нужна
  интеграция с ОС: native dialogs, filesystem и shell integration, запуск файлов
  и приложений, clipboard и platform shortcuts.
- Реализация должна предпочитать минимальную достаточную сложность и не создавать
  абстракции для гипотетических будущих функций, но не вправе упрощать Git
  semantics.
- Приложение не зависит от внешней telemetry infrastructure и не собирает
  пользовательскую аналитику в первой версии.

## Non-Goals

- Буквальный или pixel-perfect клон Git Extensions.
- Несколько репозиториев во вкладках одного окна.
- Clone и Init в обязательном MVP.
- Полноценная поддержка bare repositories.
- Специализированный UI для submodules, Git LFS и sparse checkout.
- Локализация и telemetry в первой версии.

Наличие submodules, Git LFS или иных поддерживаемых Git расширений по возможности
не должно мешать открыть основной репозиторий или повреждать его состояние.

## Acceptance Criteria

- Пользователь запускает приложение на Windows или macOS и открывает существующий
  локальный Git-репозиторий либо worktree.
- Несколько экземпляров приложения могут одновременно работать с разными
  репозиториями.
- Пользователю не требуется внутренняя информация о реализации, чтобы выполнить
  поддерживаемые Git-сценарии.
- Неописанный сценарий сохраняет Git semantics и следует подходящему поведению
  Git Extensions либо имеет явно принятое отступление.

## Verification

- Сквозные пользовательские сценарии проверяются на реальных тестовых
  репозиториях на основных платформах.
- Проверяется открытие обычного репозитория и существующего worktree.
- Проверяется независимая работа нескольких экземпляров приложения.
- Для значимых UI-изменений, когда это практически возможно, запущенное
  приложение проверяется агентом: layout, sizing, scrolling, clipping, реальные
  данные, состояния действий и resize.
