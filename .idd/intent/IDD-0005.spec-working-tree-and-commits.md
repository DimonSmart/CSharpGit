# IDD-0005.spec-working-tree-and-commits

## Intent

Пользователь явно управляет working tree и Git index на уровне целых файлов,
создает commit только из фактически staged изменений и получает защищенный от
случайной потери данных workflow.

## Behavior

- UI показывает modified, added, untracked, deleted, renamed и conflicted files.
- Staged и unstaged — независимые характеристики относительно разных Git states:
  один файл может одновременно иметь staged и дополнительные unstaged changes,
  и UI однозначно это показывает.
- Пользователь выполняет Stage file и Unstage file как отдельные явные операции.
- Обычный Commit создает commit из текущего Git index и не выполняет неявный
  stage или unstage; дополнительные unstaged changes в commit не попадают.
- Если Commit инициирован при пустом index, но непустом working tree, UI явно
  предлагает: stage all и продолжить, вернуться к выбору файлов либо отменить.
  Приложение не выбирает файлы самостоятельно.
- Intentional empty commit допустим только как явно отдельное осознанное действие.
- После успешного commit обновляются history, graph, refs, working tree и index.
- Amend last commit доступен как явно обозначенный режим и сохраняет реальную Git
  semantics.
- Пользователь может discard незакоммиченные изменения целого файла только после
  explicit confirmation.
- При закрытии репозитория или приложения непустой, еще не примененный commit
  message не теряется молча; используется confirmation, draft или иной простой и
  понятный механизм.

## Durable Architecture And Constraints

- Index остается реальным Git index, а staging — самостоятельной пользовательской
  операцией.
- Иные действия не меняют index молча, кроме неизбежной стандартной части явно
  показанной Git operation.
- Destructive operations не получают фиктивную модель Undo, если Git не
  предоставляет безопасного Undo.
- Риск потери данных обозначается явно и требует осознанного действия.

## Non-Goals

- Hunk, line или иное partial staging в MVP.
- Partial discard в MVP.
- Сложная persistent session model только ради сохранения commit message.
- Неявное включение unstaged файлов в обычный commit.

## Acceptance Criteria

- Пользователь различает staged и unstaged части одного файла и может stage или
  unstage целый файл.
- Commit включает ровно текущее содержимое index.
- Commit при пустом index не выполняет silent staging и дает явный выбор.
- Amend визуально не смешивается с обычным commit.
- Discard целого файла требует подтверждения.
- Непустой commit message не теряется молча при закрытии.

## Verification

- Проверяются все основные file states и файл с одновременными staged/unstaged
  изменениями.
- Проверяются commit с дополнительными unstaged changes, пустой index, stage all,
  cancel, intentional empty commit при его наличии и amend.
- Проверяются success и failure outcomes staging, commit и discard, последующее
  соответствие UI реальному репозиторию и защита введенного commit message.
