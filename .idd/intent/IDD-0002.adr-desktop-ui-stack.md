# IDD-0002.adr-desktop-ui-stack

## Status

Accepted

## Context

Продукту нужен единый современный desktop UI для Windows и macOS с best-effort
поддержкой Linux, общей продуктовой моделью и минимальным количеством
платформенно-специфичных реализаций.

## Decision

- Использовать .NET 10 LTS.
- Использовать Uno Platform, XAML и Skia Desktop как desktop rendering target.
- Использовать Fluent как основной design system.
- Организовать presentation layer по MVVM и отделить UI-логику от Git/domain
  logic посредством application/domain services.
- Считать `MainPage` UI shell/composition view: feature-specific application
  orchestration размещать в feature ViewModels, а code-behind оставлять для UI
  mechanics, dialog adapters и XAML-specific lifecycle.
- Предпочитать стандартные Uno controls. Custom controls и custom drawing
  применять только когда стандартных controls недостаточно; commit graph является
  ожидаемым случаем custom drawing.
- Не создавать отдельные платформенные реализации UI без необходимости.

## Alternatives Considered

- Отдельные native UI для каждой ОС отклонены из-за расхождения продуктовой
  модели и дублирования реализации.
- Собственный набор controls вместо стандартных Uno controls отклонен как
  неоправданная сложность.
- Размещение Git/domain logic непосредственно во Views или code-behind отклонено
  из-за смешения ответственности и затруднения проверки Git semantics.

## Consequences

- Основная иерархия Views и поведение остаются общими на поддерживаемых ОС, без
  требования pixel-perfect идентичности.
- Views, ViewModels, application/domain services, Git integration и
  infrastructure/platform integration образуют отдельные границы.
- ViewModels не являются обертками над command-line strings; детали выполнения
  Git скрыты за service boundary.
- `MainPage` не должен напрямую владеть Git feature workflows, если для feature
  выделен Presentation owner; feature ViewModel использует существующий repository
  lifecycle вместо дублирования refresh infrastructure.
- Реализованные feature-level Presentation owners для Tags и Worktrees —
  `TagsViewModel` и `WorktreesViewModel`; они работают с явным repository context,
  а `MainPage` сохраняет только UI-specific adapters и mechanics.
  Текущая композиция этих features: `OpenRepositoryViewModel` предоставляет
  repository lifecycle/context, к которому подключены `TagsViewModel` и
  `WorktreesViewModel`; application capabilities остаются внутри соответствующих
  feature ViewModels.
- Платформенная интеграция остается допустимой там, где она необходима ОС.
