# IDD-0027.spec-compact-worktree-names

## Intent

Repository Tree worktree rows remain compact and navigable when branch names are long while making the repository primary worktree and the current CSharpGit worktree unambiguous. Stable Repository Tree identity/reconciliation from IDD-0012 remains based on the full worktree path.

## Primary label

A branch worktree displays its full local branch name as the primary label. The worktree path is not part of the primary row label.

A detached worktree displays the last directory name from its worktree path, handling a trailing `/` or `\\`. If no directory name can be derived, use short HEAD; if HEAD is unavailable, use `detached`.

The primary label is derived presentation data. `WorktreeInfo` remains the semantic source and worktree logical identity remains the stable worktree path.

## Primary and current worktrees

`WorktreeInfo.IsPrimary` identifies the Git main worktree. `GitWorktreeParser` derives it from `git worktree list --porcelain -z`: the first successfully parsed valid worktree record is primary and all following records are not. Primary is not inferred from branch name, directory name, repository root heuristics, current state, or Repository Tree position.

`WorktreeInfo.IsCurrent` remains independent and is derived by the existing platform-aware normalized-path comparison with `Repository.WorkingDirectory`.

The primary worktree displays a compact neutral `PRIMARY` trailing badge. Current worktree presentation remains row state only: bold primary label plus the existing weak accent background. No `CURRENT`, `ACTIVE`, `OPEN`, or equivalent text is added. Primary and current may refer to the same worktree or different worktrees.

## Worktree state

Detached, locked and prunable state remains visible independently from the trimmable primary label and from primary/current state. Lock reason is not expanded into the row; the full reason remains available in the tooltip.

## Width-dependent presentation

A worktree primary label that does not fit uses one Unicode middle ellipsis (`…`), preserving both prefix and suffix while giving a small preference to the suffix. Trimming is based on actual rendered text width after indentation, guides, icons, spacing, the fixed `PRIMARY` badge and state indicators have consumed their space. It must not use a fixed character count and must not split Unicode grapheme clusters.

The `PRIMARY` badge is a fixed trailing element and remains visible when the primary label is long. The primary label receives the remaining width and is shortened first.

If the full label fits, it is displayed unchanged. At very narrow widths the representation degrades toward `…` without forcing Repository Tree wider.

Resize recomputes only presentation text. It must not mutate `RepositoryTreeNode.Name`, `WorktreeInfo`, logical identity, selection/expansion state, or trigger repository refresh/reconciliation.

## Tooltip

Every worktree exposes full untrimmed semantic values in its tooltip:

- branch worktree: full `Branch` and `Path`;
- detached worktree: full `Path` and detached state;
- `Primary worktree` when `IsPrimary` is true;
- `Current worktree` when `IsCurrent` is true;
- locked/prunable state when applicable;
- full lock reason when present.

Primary and current tooltip lines are added independently. Tooltip content never derives from the width-trimmed label.

## Context menu

Worktree context menu includes a clipboard group:

- `Copy branch name` only when `WorktreeInfo.Branch` exists;
- `Copy worktree path` for every worktree.

Both copy exact source values, remain available while the repository is busy, do not execute Git commands, and do not cause refresh/reconciliation.

`Remove Worktree` is not offered for the primary worktree or the current worktree. Existing lock-state restrictions remain. The semantic remove operation also rejects `IsPrimary` and `IsCurrent` before executing `git worktree remove`.

Other existing worktree management actions remain unchanged.

## Ordering

Primary worktree remains first. All remaining worktrees sort case-insensitively by their full primary label: branch name for branch worktrees and directory name/fallback for detached worktrees. Equal labels use the full worktree path as deterministic case-insensitive tie-breaker. `IsCurrent` does not affect ordering. Width trimming never affects sorting.

## Interaction and layout

Existing Repository Tree selection, keyboard navigation, expand/collapse, hierarchy guides, icons, current-worktree emphasis, row height, hit area, double-click behavior and worktree actions remain unchanged. Current styling does not set TreeView selection. The primary label consumes only the width remaining after fixed row presentation elements, including the `PRIMARY` badge and worktree state indicators.

The `PRIMARY` badge is theme-aware, low-emphasis, non-clickable and must not intercept row interaction.

## Acceptance Criteria

- Worktree rows no longer show path beside the primary label.
- Branch and detached labels follow the rules above.
- The first valid parsed Git worktree record is the single semantic primary worktree when worktrees exist.
- `IsPrimary` and `IsCurrent` remain independent; branch `main` has no special meaning for primary detection.
- Primary worktree has a fixed neutral `PRIMARY` badge; current worktree has only the existing bold/accent row styling.
- Long labels use rendered-width, Unicode-safe middle ellipsis and restore fully when space returns; the `PRIMARY` badge remains visible.
- Resize does not mutate logical presentation/model state or reconcile the tree.
- Detached/locked/prunable state remains discoverable; full lock reason is available in tooltip.
- Tooltip uses full semantic values and independently reports primary/current state.
- Copy branch/path actions copy exact full values and are independent of busy state.
- Primary-first ordering, current-independent ordering, full-label/path secondary ordering, and stable path identity are preserved.
- `Remove Worktree` is unavailable for primary/current worktrees and the semantic remove operation rejects both states.
- Ordinary refresh continues to reuse unchanged worktree nodes.
