# IDD-0012.spec-repository-tree-navigation

## Intent

Repository Tree должен оставаться компактной и предсказуемой навигацией по refs даже в repository с большим количеством именованных веток.

Спецификация уточняет presentation semantics дерева веток поверх IDD-0010 и не меняет Git model или ref semantics из IDD-0006.

## Branch hierarchy and ordering

Local и remote branch names, содержащие `/`, отображаются иерархически как branch folders.

На каждом уровне branch hierarchy порядок одинаков:

1. непосредственные branch leaves без следующего path segment;
2. затем branch folders;
3. внутри каждой группы элементы сортируются по имени без учета регистра.

Current local branch не меняет позицию в сортировке. Она определяется существующим `IsCurrent` и визуально выделяется жирным именем с чётким accent-подчёркиванием; полупрозрачный accent background и эффект свечения не используются. Home icon текущей local branch использует тот же accent color. Отдельная вертикальная accent-полоска слева от icon не отображается. Галочка и дополнительные текстовые current-маркеры не используются.

Current-branch presentation не является selection state. Обычные TreeView hover, selection, keyboard focus и expand/collapse продолжают работать независимо; selected item должен оставаться визуально сильнее current-branch emphasis. Цвета current-branch оформления берутся через `ThemeResource`, чтобы поведение одинаково поддерживало dark/light theme.

То же правило branch hierarchy рекурсивно применяется внутри branch folders и для remote branch hierarchy.

## Hierarchy guide lines and expanders

Repository Tree отображает классические graphical hierarchy guides для всех nested nodes. Root-level groups сами по себе не получают connector lines; guides начинаются у их children.

Для каждого nested node presentation metadata сохраняет для каждого ancestor level, есть ли у соответствующего ancestor следующие siblings, а также является ли текущий node последним sibling. На основе этих данных:

- ancestor с последующими siblings получает непрерывную vertical line;
- ancestor без последующих siblings оставляет пустой guide column;
- обычный текущий child получает full vertical + horizontal connector (`├` geometry);
- последний child получает top-half vertical + horizontal connector (`└` geometry).

Guides являются graphical XAML presentation, а не текстовыми box-drawing characters. Линии визуально выражены сильнее обычных divider lines: имеют толщину около 1.5 px, используют theme-aware neutral/control stroke brush и rounded caps/junctions без hard-coded RGB.

У nodes с children стандартный detached chevron заменяется компактным Windows-style square expander с `+` в collapsed state и `−` в expanded state. Квадрат расположен непосредственно на текущей hierarchy line, так что expander и connector воспринимаются как единая графика дерева. Root-level expandable groups также получают square expander, но не получают лишнюю root connector line. Leaf nodes не получают expander box.

Square expander является presentation-only control над штатным `TreeViewItem.IsExpanded`: click/tap меняет именно `TreeViewItem.IsExpanded`, а keyboard expand/collapse и остальная TreeView semantics остаются штатными. Expander не должен менять selection/current-branch semantics или добавлять новый hierarchy spacing.

Repository Tree сохраняет штатный `TreeViewItem` template и его expander slot, чтобы не менять исходные indentation, row metrics и platform visual states. Стандартные chevron glyphs подавляются через пустые `CollapsedGlyph` / `ExpandedGlyph`, а не через `GlyphOpacity`: Uno при container preparation и при изменении children сам восстанавливает `GlyphOpacity` в `1` для expandable nodes. Благодаря сохранению штатного slot содержимое не сдвигается влево, а compact row height продолжает определяться существующим `Height.DataRow`. Changed Files tree продолжает использовать штатные chevrons.

Guide columns и expanders используют фактическую indentation `TreeViewItem`, чтобы не добавлять дополнительный hierarchy spacing и не мешать icons, selection и current-branch emphasis. Derived hierarchy-guide metadata может пересчитываться проходом по stable presentation tree после reconciliation; `PropertyChanged` отправляется только узлам, чья фактическая guide geometry изменилась.

## Default branch marker

Remote default branch и local branch, которая действительно tracks эту remote branch, отмечаются одинаковой метафорой home icon и используют одинаковый accent style/color.

Current local branch также использует accent home icon как часть current-branch emphasis. Если current local branch одновременно является local default marker, отображается один home icon, без дублирования.

Default marker является дополнительным индикатором и не заменяет current-branch emphasis, branch type, selection или ahead/behind state. Совпадение имени local branch с remote default branch само по себе не создает default marker.

Если default branch неизвестна, default home marker не отображается.

## Initial expansion

После первого построения Repository Tree для repository:

- `Branches` раскрыт;
- путь branch folders до current local branch раскрыт, чтобы current branch была видима;
- `Remotes` свернут;
- отдельные remote nodes свернуты;
- `Tags` и `Stashes` свернуты.

Если current branch находится непосредственно под `Branches`, дополнительные branch folders автоматически не раскрываются.

## Expansion state during the session

Ручное expand/collapse является пользовательским presentation state и сохраняется при обычных repository refresh/mutations благодаря сохранению identity существующих `RepositoryTreeNode`.

Обычный refresh не должен collapse/expand существующие groups, remotes или branch folders и не должен заменять их presentation objects. Stable expansion storage остаётся fallback для nodes, которые действительно создаются заново.

При переключении current local branch путь до новой current branch автоматически раскрывается, даже если соответствующие folders ранее были свернуты. После этого последующие refresh сохраняют новое состояние.

При открытии другого repository presentation session начинается заново: expansion state сбрасывается и применяется initial expansion policy нового repository.

## Architecture

Expansion state, selection continuity и hierarchy-guide metadata принадлежат presentation layer и не являются частью Git/domain state.

Repository Tree является долгоживущей presentation structure для открытого repository. Новый repository snapshot сначала преобразуется в complete desired logical tree со stable keys, после чего existing tree reconciles с ним:

- одинаковый logical key повторно использует тот же `RepositoryTreeNode`;
- изменившиеся presentation data обновляются на существующем node;
- новые/исчезнувшие/reordered nodes выражаются `Add` / `Remove` / `Move`;
- `_repositoryTreeRoots` и `RepositoryTreeNode.Children` не получают `Reset` при ordinary refresh;
- branch folders идентифицируются полным logical prefix, а remote folders также remote scope;
- stash identity основана на stable stash commit, а не на positional `stash@{n}`;
- worktree identity основана на stable worktree path.

Branch grouping и sorting строятся в desired tree и затем reconciles без `Clear() + Add everything`. Tag order остаётся existing source order; изменение порядка выполняется через `Move` с сохранением nodes.

Один применённый repository-state snapshot коалесцируется максимум в одну Repository Tree reconciliation. `HeadDisplay`, `CurrentOperation`, `IsBusy` и другие non-structural properties сами по себе не инициируют structural tree update.

Worktrees загружаются отдельным source и reconciles отдельно: stable `Worktrees` root и его children обновляются без перестройки Branches/Remotes/Tags/Stashes; association local branch ↔ worktree обновляется на existing local branch node.

Если selected logical node сохраняется после reconciliation, сохраняется тот же selected presentation object. При удалении selection fallback выбирается детерминированно внутри той же logical area: next sibling, previous sibling, surviving parent, затем ближайший surviving ancestor/root.

Полный rebuild допустим только на repository lifecycle transition (initial/open/close/change) или как явно диагностированный exceptional recovery после inconsistent presentation state. Ordinary branch/tag/stash/worktree/fetch/manual refresh не используют full rebuild fallback.

Current-branch decoration является presentation-only state, вычисляемым из существующего `IsCurrent`. Оно не должно устанавливать `TreeViewItem.IsSelected`, менять selected item или перехватывать pointer/focus interaction строки.

## Acceptance Criteria

- На любом уровне branch leaves отображаются раньше branch folders.
- Branch leaves сортируются alphabetically case-insensitive.
- Branch folders сортируются alphabetically case-insensitive.
- Current branch emphasis не влияет на порядок.
- Nested Repository Tree items отображают classic parent/child graphical guide lines.
- Ancestor vertical line продолжается только пока у соответствующего ancestor есть следующий sibling.
- Intermediate child и last child различаются `├`/`└` geometry; branch последнего child визуально завершается на середине его row.
- Root-level groups не получают лишних connector lines, при этом их nested children получают guides.
- Guide lines работают как минимум на трех уровнях вложенности для local и remote branches.
- Guide lines имеют толщину около 1.5 px, rounded ends/junctions, используют theme-aware neutral/control brush без hard-coded RGB и не увеличивают row height или hierarchy spacing.
- Expandable Repository Tree nodes используют compact square `+ / −` expander вместо detached chevron; square расположен на hierarchy line.
- Root expandable groups получают square expander без root connector, leaf nodes не получают expander.
- Mouse/touch expander interaction меняет штатный `TreeViewItem.IsExpanded`; keyboard expand/collapse продолжает работать.
- Guide/expander rendering не мешает icons, selection, current-branch emphasis, context menu или double-click behavior.
- Current local branch отображается жирным начертанием имени, чётким accent-подчёркиванием и accent home icon; полупрозрачный accent background, эффект свечения, отдельная вертикальная accent-полоска слева от icon, галочка и дополнительный текстовый current marker отсутствуют.
- Current-branch decoration использует `ThemeResource`, работает в dark/light theme и не ухудшает читаемость имени; обычный active TreeView selection остаётся визуально сильнее.
- `IsCurrent` не устанавливает обычный TreeView selection state; hover, selection, keyboard focus и expand/collapse сохраняют штатное поведение.
- Remote default branch и tracking local counterpart используют одинаковый accent home marker color.
- Current local branch и local default branch не создают два home icon на одной строке, если это одна и та же branch.
- Default marker сосуществует с current-branch emphasis, selection, ahead/behind и branch tree behavior без изменения их semantics.
- `Branches` initially expanded и current branch path видим.
- `Remotes`, remote nodes, `Tags` и `Stashes` initially collapsed.
- Ручное раскрытие или сворачивание сохраняется после ordinary repository refresh/mutation без замены unchanged nodes.
- Переключение current branch раскрывает путь до новой current branch.
- Открытие другого repository не наследует expansion state предыдущего repository.
- Local и remote branches остаются Git-semantically неизменными; меняется только presentation behavior.
- Unchanged logical nodes сохраняют reference identity; ordinary refresh не вызывает `Reset` root/children collections.
- Create/delete branch, remote ref changes, tag reorder, stash reindex и worktree changes изменяют только затронутые nodes/subtrees.
- Surviving stash сохраняет node identity при `stash@{1} -> stash@{0}`.
- Selected surviving node сохраняет selection; удалённый node получает deterministic fallback в той же logical area.

## Verification

Проверять как минимум repository с:

- root branches `main`, `develop`;
- folders `feature/*`, `bugfix/*`;
- nested branches `feature/ui/dark-theme`, `feature/ui/tree-lines`, `feature/backend/api`;
- несколькими remotes;
- current branch внутри nested folder;
- remote default branch и tracking/non-tracking local branches.

Проверить начальное состояние, ручной expand/collapse с последующим Refresh, switch между root/nested current branches, правильное продолжение/завершение hierarchy guides на intermediate/last siblings, local и remote guides минимум на трех уровнях, square `+ / −` expanders на root и nested expandable nodes, отсутствие expander у leaves, mouse и keyboard expand/collapse, light/dark theme, чёткое accent-подчёркивание и жирное имя current branch без background или свечения, отдельной вертикальной accent-полоски, галочки и текстового маркера, независимость current state от TreeView selection и одинаковый accent color local/remote home markers.
