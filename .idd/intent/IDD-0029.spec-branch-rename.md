# IDD-0029.spec-branch-rename

## Intent

Пользователь может переименовать local branch прямо из Repository Tree. Полное Git
branch name является semantic identity операции; виртуальные branch folders остаются
только presentation-группировкой по `/`.

## Related Specifications

- IDD-0006 — refs and remotes
- IDD-0009 — desktop experience and mutation/error handling
- IDD-0012 — Repository Tree navigation and reconciliation

## Behavior

- Local branch получает `Rename…` в context menu и F2, когда keyboard focus находится
  в Repository Tree и визуально выбран local branch node.
- Local branch также можно перемещать drag & drop в существующую local branch folder
  или в корень `Branches`; это namespace rename, а не reorder дерева.
- Все точки входа используют один Presentation mutation workflow и передают exact
  `GitBranch`, а не восстанавливают target из глобального selection state.
- Rename dialog редактирует полное `GitBranch.Name`. Пустое после `Trim()` и имя,
  ordinal-равное текущему, не запускают mutation.
- UI разрешает rename текущей branch и branch, checkout-нутой в linked worktree.
  Доступность определяется открытым repository, отсутствием busy state и
  `RepositoryOperation.None`.

## Drag And Drop Namespace Move

- Drag source может быть только local branch node с `GitBranch` в `Value`.
- Допустимые destinations: exact `Branches` root по stable tree identity и
  `BranchFolder` с `BranchFolderInfo.Scope == Local`.
- Remote branch folders, branches, tags, worktrees и остальные groups не являются
  допустимыми destinations; remote branches и прочие nodes не являются drag sources.
- Source фиксируется при `DragItemsStarting` из фактически dragged item. Destination
  определяется из фактического node под pointer. Repository Tree selection не является
  source of truth ни для одной стороны операции.
- Leaf вычисляется из полного `GitBranch.Name`: destination folder заменяет только
  prefix до последнего `/`; drop на `Branches` удаляет prefix. Display/decorated node
  name не участвует в вычислении.
- Drop в текущую folder/root, дающий ordinal-identical branch name, является no-op без
  Git mutation и специального refresh.
- Tree использует custom move semantics с drag/drop enabled и generic reorder disabled.
  Branch/folder nodes вручную не reparent-ятся до или после mutation.
- `CanRenameBranch()` проверяется при старте drag и непосредственно перед mutation.
  Stale source не заменяется текущим selection; исчезнувший ref отклоняется normal Git
  mutation/error handling.
- Current branch и linked-worktree branch не получают дополнительных D&D ограничений.

## Git Semantics

- `IReferenceService.RenameBranchAsync(repository, oldName, newName)` является
  переиспользуемой branch operation.
- Git implementation выполняет `git branch -m <oldName> <newName>` через существующий
  `RunGitForMutationAsync` / `GitCommandExecutor` с отдельными arguments.
- Existing `ValidateRefName` используется только как базовая application validation;
  окончательная допустимость имени, namespace conflicts и состояние refs определяются
  Git.
- Rename не реализуется через create/delete и не изменяет `.git`, refs, worktree HEAD,
  reflog или branch configuration вручную.
- Local rename не переименовывает remote branch и не переписывает upstream. Поведение
  tracking configuration остаётся штатной семантикой `git branch -m`.

## Mutation And Presentation State

- Rename выполняется одним `_viewModel.RunMutationAsync` с error context
  `Could not rename local branch`; normal repository refresh и tree reconciliation
  остаются authoritative.
- Dialog rename и drag/drop namespace move сходятся в одном Presentation-level
  workflow до вызова `IReferenceService.RenameBranchAsync`.
- Repository Tree не перемещает nodes вручную. Изменение `feature/a` → `bugfix/a`
  воспринимается как исчезновение одного local ref и появление другого.
- Если `_activeReference` равен старому branch name, внутри mutation после успешного
  Git rename он заменяется новым именем и label обновляется до `Branch: <newName>` до
  post-mutation scoped-history reload.
- После успешного rename worktree presentation проходит через существующий worktree
  refresh mechanism; `_worktrees` вручную не изменяется.
- Сохранение визуального tree selection после rename является необязательным и не
  должно требовать отдельного generic state-management mechanism.

## Non-Goals

- Rename или drag целой virtual branch folder.
- Remote branch rename, push/delete remote refs или Git hosting API operations.
- Generic Repository Tree reordering или branch-on-branch drop.
- Собственная grammar Git ref names или parser Git stderr.
- Manual changes to `.git`, worktree metadata, HEAD, reflog or branch config.

## Acceptance Criteria

- Context menu и Repository Tree F2 запускают единый rename workflow только для local
  branches.
- Local branch можно drag/drop переместить в existing local branch folder или в exact
  `Branches` root; новое имя строится как `<destination-prefix>/<source-leaf>` либо
  `<source-leaf>` для root.
- Source leaf берётся из `GitBranch.Name`; linked-worktree decoration не влияет на имя.
- Remote branches и прочие nodes не являются drag sources; remote folders и остальные
  tree nodes не являются destinations.
- Generic Repository Tree reorder отключён; normal reconciliation остаётся
  authoritative и D&D не reparent-ит nodes вручную.
- Same-folder/root D&D no-op не запускает Git mutation.
- Dialog rename и D&D используют один Presentation mutation workflow.
- Current и linked-worktree branches не блокируются application code.
- Rename выполняется через `IReferenceService` и `RunGitForMutationAsync`.
- Namespace move отражается через normal Repository Tree reconciliation.
- Scoped branch history продолжает ссылаться на переименованную branch.
- Remote refs не изменяются, existing upstream сохраняется согласно Git semantics.
- Git failures проходят через existing mutation error handling с Git diagnostic.
- Integration tests покрывают current branch, namespace moves/conflicts, linked
  worktree, tracking branch, composite names и same-name guard; Desktop tests
  дополнительно фиксируют D&D source/destination eligibility, target-name calculation,
  custom TreeView contract и общий Presentation mutation workflow.
