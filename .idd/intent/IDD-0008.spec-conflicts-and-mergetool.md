# IDD-0008.spec-conflicts-and-mergetool

## Intent

Конфликтные и незавершенные Git operations представлены как реальное,
восстанавливаемое состояние репозитория. Пользователь видит контекст, разрешает
каждый conflict подходящим способом и управляет lifecycle операции без догадок со
стороны приложения.

## Behavior

- UI показывает незавершенную operation, список конфликтующих файлов, состояние
  каждого conflict и применимые действия.
- Для conflict пользователь может открыть файл для ручного редактирования,
  запустить настроенный внешний merge tool, stage разрешенный файл и выбрать
  local/current либо remote/incoming version, когда выбор имеет однозначную Git
  semantics.
- Для add/add, modify/delete, delete/modify, binary и других нетекстовых случаев
  UI предлагает подходящие действия выбора версии, сохранения или удаления.
- Contextual labels учитывают различие смысла ours/theirs в merge и rebase и не
  вводят пользователя в заблуждение механическими названиями.
- Доступны Continue, Abort и Skip только для тех operations, где Git их
  поддерживает.
- Команда Continue, запущенная из приложения, не открывает скрытый текстовый
  editor и не ожидает ввода вне UI приложения. Если Git требует сообщение для
  продолжения операции, приложение сохраняет или передает допустимое сообщение
  без интерактивного editor workflow.
- Открытие editor, завершение процесса mergetool или закрытие dialog само по себе
  не означает resolved state. После действия приложение перечитывает repository
  и index; только их фактическое состояние определяет resolved/unresolved.
- Merge и rebase in progress обнаруживаются при открытии repository, Refresh,
  возвращении приложения в активное состояние и после Git command или mergetool.
- После закрытия и повторного открытия приложения пользователь может продолжить
  разрешение conflicts, Continue или Abort существующей операции.
- Пользователь настраивает внешний merge tool: tool, executable/path при
  необходимости и command/arguments. Предпочитается стандартная global или
  repository-local Git configuration; допускаются известные presets, custom tool
  и custom command.
- Mergetool получает применимые BASE, LOCAL, REMOTE и MERGED representations по
  стандартной Git mergetool semantics.
- `Open in <configured merge tool>` запускает tool только для выбранного файла.
  Отдельный `Start mergetool` запускает repository-level последовательный
  workflow; обе операции доступны и не заменяют друг друга.

## Durable Architecture And Constraints

- In-progress state не существует только в памяти приложения и всегда выводится
  из фактического Git repository.
- Приложение не угадывает правильное разрешение conflict и не считает внешний
  process источником resolved state.
- Обычные Git-команды, инициированные UI, выполняются без неявного запуска
  интерактивного текстового editor. Это ограничение не запрещает явно
  запрошенный пользователем внешний mergetool или ручное открытие файла.
- Стандартная Git mergetool configuration используется там, где это практически
  возможно, вместо несовместимого собственного формата.

## Non-Goals

- Встроенный полноценный graphical three-way merge editor в MVP.
- Автоматический выбор правильной стороны conflict.
- Подмена repository-level mergetool workflow запуском tool только для файла или
  наоборот.

## Acceptance Criteria

- Пользователь видит conflicts и корректные contextual actions для merge и
  rebase, включая нестандартные conflict types.
- Ручное редактирование, выбор стороны, удаление и внешний mergetool отражаются как
  resolved только после фактического изменения Git state.
- Пользователь может stage resolved conflict и выполнить применимый Continue,
  Skip или Abort.
- Оба режима внешнего mergetool работают по своему scope.
- Незавершенные merge/rebase переживают перезапуск приложения.
- Ошибочная конфигурация или отсутствие внешнего tool дают понятную диагностику.

## Verification

- Проверяются textual, add/add, modify/delete, delete/modify и binary conflicts в
  merge и rebase.
- Проверяются contextual labels, выбор каждой применимой стороны, ручное
  разрешение, staging и отказ считать файл resolved без изменения Git index.
- Проверяются single-file и repository-level mergetool workflows, передача
  representations и failure diagnostics.
- Проверяются Continue, Skip, Abort и восстановление незавершенной операции после
  полного перезапуска приложения.
- Проверяется продолжение разрешенного merge-конфликта без запуска
  интерактивного текстового editor и без ожидания ввода вне приложения.
