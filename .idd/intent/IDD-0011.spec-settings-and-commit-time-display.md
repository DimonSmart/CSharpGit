# IDD-0011.spec-settings-and-commit-time-display

## Intent

CSharpGit предоставляет расширяемое отдельное окно глобальных настроек, единый
способ отображения времени коммитов, глобальное управление appearance и
управляемое пользователем диагностическое логирование, чтобы пользователь мог
менять presentation/diagnostics behavior без изменения Git semantics или порядка
истории.

## Behavior

- Settings открываются в отдельном desktop window.
- Слева находится вертикальная навигация по разделам настроек. Доступны страницы
  `General` и `Diagnostics`; архитектура допускает добавление новых страниц без
  перестройки окна.
- В начале `General`, перед `Commit time display`, находится секция `Appearance`.
- Appearance поддерживает ровно три глобальных режима: `System`, `Light`, `Dark`.
  `System` является default и самостоятельным сохраняемым значением; он снимает
  принудительный Light/Dark override и делегирует фактическую тему Uno/platform
  theme infrastructure. Фактический результат системной темы не сохраняется.
- Изменение appearance применяется сразу ко всем открытым top-level visual roots,
  включая Main и Settings, а новый root при регистрации сразу получает текущий
  глобальный режим. Отдельной темы repository/workspace/window нет.
- Выбранный appearance сохраняется между запусками и применяется к main root до
  первого показа окна. Старые settings без theme field используют `System`.
- Неизвестное или некорректное сохранённое значение theme безопасно трактуется
  как `System` и не должно сбрасывать остальные корректные settings.
- Отдельный `Appearance` dialog и отдельный пункт `Appearance…` в меню не
  используются; appearance изменяется только через `Settings → General`.
- В `General` настраивается `Commit time display`.
- Настройка времени глобальна для приложения, сохраняется между запусками и
  применяется сразу ко всем отображениям времени коммитов.
- Поддерживаются только три основных режима времени:
  - `Smart` — режим по умолчанию и рекомендуемый: коммиты младше 30 дней
    отображаются относительным временем; более старые — календарной датой, без
    года для текущего года и с годом для предыдущих лет.
  - `Relative` — всегда показывает возраст (`3 hours ago`, `12 days ago`,
    `8 months ago`).
  - `Absolute` — всегда показывает локальные дату и время в компактном стабильном
    формате `yyyy-MM-dd HH:mm`.
- Hover над временем всегда показывает точные локальные дату, время, секунды и
  UTC offset независимо от выбранного режима.
- Relative/Smart representation обновляется во время работы приложения, чтобы
  видимое значение не оставалось устаревшим надолго.
- Источником времени остается `CommitHistoryItem.AuthoredAt`; эта настройка не
  меняет Git timestamp semantics.
- Сортировка, фильтрация и другие операции работают по исходному timestamp, а не
  по отформатированной строке.
- Presentation использует единый reusable component/formatter для commit time,
  а не дублирует форматирование в отдельных views.
- В `Diagnostics` пользователь может включить или выключить session file logging.
  Логирование выключено по умолчанию.
- Для логирования доступны уровни `Trace`, `Debug`, `Information`, `Warning`,
  `Error` и `Critical`; default level — `Information`.
- Изменение enabled state или log level применяется сразу и сохраняется между
  запусками.
- При выключенном logging новые file-log записи не создаются; logger не должен
  создавать session log file только из-за запуска приложения.
- Session logs сохраняются в application-data каталоге CSharpGit и имеют
  ограниченную retention старых файлов.

## Durable Architecture And Constraints

- Глобальные settings доступны через `IAppSettingsService`; сохранённый appearance
  представлен UI-независимым `ApplicationThemeMode` и имеет единственный source
  of truth в settings service.
- `Application` и persistence infrastructure не зависят от `ElementTheme`,
  `FrameworkElement`, `Window` или других Uno/WinUI UI types.
- Преобразование `ApplicationThemeMode` в UI theme и применение темы к
  зарегистрированным roots централизованы только в Presentation layer.
- Presentation theme manager подписывается на общий settings change signal,
  перечитывает текущее значение theme, применяет его только при необходимости и
  корректно маршалит изменение на dispatcher соответствующего root.
- `OpenRepositoryViewModel` не хранит и не знает application appearance.
- Persistence реализована вне Git/domain logic; поврежденный или недоступный
  settings file не мешает запуску и приводит к безопасным defaults. Для
  отсутствующего/некорректного theme default — `System`; для commit time —
  `Smart`; logging — disabled с уровнем `Information`.
- Theme persistence использует человекочитаемые строковые значения `System`,
  `Light`, `Dark`. Ошибка записи следует общей optimistic settings semantics:
  новое значение уже является текущим и публикуется UI, exception возвращается
  вызывающему коду без специального rollback.
- Изменение настройки публикуется текущим views/runtime сразу; сохранение
  выполняется в пользовательскую application-data директорию.
- File logger поддерживает runtime enable/disable и minimum level без restart.
- Диагностические механизмы не должны быть встроены в commit-graph renderer как
  обязательный production tracing; renderer остается независимым от file logger.
- UI использует стандартные Uno/Fluent controls и остается общим для Windows,
  macOS и других Skia Desktop targets.

## Non-Goals

- Настройки на уровне отдельного repository, workspace или окна.
- Material/Cupertino switching, custom theme packs, accent colors или
  пользовательские цветовые схемы.
- Собственный OS theme watcher или platform-specific ручное определение
  системной Light/Dark темы.
- Пользовательский формат даты/времени.
- Изменение AuthorDate/CommitterDate semantics.
- Синхронизация настроек между устройствами.
- Отдельные log-level настройки для каждого subsystem/category.

## Acceptance Criteria

- `Settings…` из главного окна открывает отдельное окно с вертикальной навигацией
  слева и страницами `General` и `Diagnostics`.
- `General → Appearance` находится перед `Commit time display` и содержит ровно
  `System`, `Light`, `Dark`; отдельные Appearance dialog/menu отсутствуют.
- Appearance применяется без restart ко всем открытым roots, а новые roots сразу
  получают текущее значение.
- Theme сохраняется строкой и восстанавливается при следующем запуске; main root
  получает сохранённый режим до `Window.Activate()`.
- `System` является default, сохраняется именно как `System` и не фиксирует UI на
  Light/Dark.
- Старые settings без theme остаются совместимыми, а неизвестное значение theme
  не сбрасывает остальные корректные settings.
- Theme больше не является состоянием `OpenRepositoryViewModel`; UI mapping и
  root propagation находятся только в Presentation.
- В `General` доступны Smart, Relative и Absolute; Smart выбран при первом
  запуске.
- Переключение режима сразу изменяет видимые времена в history и commit details.
- После перезапуска выбранный режим восстанавливается.
- Tooltip каждого commit time показывает точное local timestamp с offset.
- Smart использует relative до 30 дней и calendar date после порога.
- Relative корректно формирует основные единицы времени, включая future clock
  skew, а Absolute имеет стабильный компактный формат.
- В `Diagnostics` пользователь может включить file logging и выбрать любой из
  шести поддерживаемых уровней.
- Logging disabled + Information являются defaults для нового/старого settings
  file, в котором logging fields отсутствуют.
- Logging settings сохраняются и применяются без restart.
- При disabled logging запуск приложения не создает новый session log file.
- Commit graph не зависит от удаленного экспериментального
  `CommitGraphDiagnostics` tracing layer.

## Verification

- Behavioral persistence tests реально читают/пишут временный `settings.json` и
  фиксируют string theme serialization, restore, backward compatibility,
  tolerant parsing, invalid enum и точную `Changed` semantics.
- Desktop UI contract tests фиксируют Appearance placement/cleanup,
  Presentation-only theme manager, отсутствие repository theme state и startup
  order до activation.
- Desktop runtime check меняет theme через `IAppSettingsService`, проверяет
  `System → Light → Dark → System` и одновременное обновление Main + Settings.
- Unit tests фиксируют поведение formatter для Smart, Relative, Absolute и
  future clock skew.
- Settings contract test фиксирует наличие Diagnostics UI, persisted logging
  settings и отсутствие обязательного commit-graph diagnostics layer.
- Desktop build проверяет XAML, settings page и reusable commit-time control
  вместе с основным приложением.
- Ручная platform smoke-проверка может дополнительно подтвердить, что возврат к
  `System` после принудительного Light/Dark снова следует фактической OS theme;
  обычный CI не обязан менять настройки ОС.
