# IDD-0022.spec-git-console

## Intent

CSharpGit предоставляет встроенную session-level Git Console, чтобы пользователь
мог видеть реальные Git CLI commands, запускаемые приложением, их arguments,
working directory, live stdout/stderr, exit code и duration без превращения
основного workspace в постоянно открытый terminal.

## Behavior

- Git Console располагается в нижней части repository workspace непосредственно
  над status bar и по умолчанию скрыта.
- Status bar показывает последнюю релевантную Git command и является основной
  ручной точкой входа в console. В обычном режиме приоритет имеет последняя User
  command; в режиме All commands допустима последняя command любого вида.
- Console показывает session history newest-first и имеет фильтр `User commands` /
  `All commands`; default — `User commands`.
- История содержит максимум 100 последних Git CLI invocations по всей session.
  Лимит фиксированный и не является пользовательской настройкой. При добавлении
  101-й записи удаляется самая старая.
- Каждая command появляется в истории сразу после успешного запуска process со
  status `Running`, сохраняет один presentation identity на всём lifecycle, а
  после завершения обновляется до `Succeeded`, `Failed` или `Cancelled` вместе с
  exit code и окончательной duration.
- stdout и stderr поступают в history и details во время выполнения command, а не
  только после завершения. Output других или невидимых commands не должен
  заставлять details выбранной command обновляться.
- Git progress, использующий carriage return (`\r`) для перезаписи текущей строки,
  отображается как обновляющаяся logical line, а не как последовательность
  дублирующихся progress-строк. Captured diagnostic state при этом сохраняется
  согласно существующим application-level capture rules без presentation-specific
  normalization.
- Captured diagnostic state и presentation diagnostic text — разные представления:
  machine-readable Git delimiters остаются в captured stdout/stderr, но перед
  передачей в general-purpose XAML text controls Presentation кодирует UI-unsafe
  control characters в deterministic visible form.
- Для поддерживаемых пользовательских Git operations, где redirected stderr иначе
  скрывает progress, CSharpGit может принудительно включать документированный Git
  progress. Явные `--progress`, `--no-progress` и quiet options пользователя имеют
  приоритет; progress не включается универсально для всех subcommands или Internal
  commands.
- Пока command находится в `Running`, console показывает увеличивающийся elapsed
  time без перестройки списка command.
- User/Internal — семантическая классификация назначения invocation, а не только
  Git subcommand. Команды прямого пользовательского действия являются User;
  команды чтения состояния и данных UI являются Internal.
- Console details показывают command, working directory, started time, duration,
  exit code, stdout и stderr. Вывод моноширинный, selectable и copyable.
- `Copy command` копирует человекочитаемую shell-like Git command. `Copy all`
  использует актуальное accumulated diagnostic state выбранной command, включая
  partial output ещё выполняющейся command.
- Console не является interactive terminal: ввод произвольных commands и Run again
  отсутствуют.
- Manual open выбирает последнюю User command, иначе последнюю Git command; при
  пустой истории показывается нейтральное empty state.
- Обычные lifecycle/output events не меняют manual selection. Selection меняется
  только при существующих manual/auto-open сценариях или если выбранная запись
  реально вытеснена session history limit.
- Git Console использует единую single-selection модель: визуально выбранная строка,
  selected activity и показанные details относятся к одной activity. Если visible
  history непуста, существует одна актуальная selection; для пустой history
  selection и details очищены.
- Shortcut toggles console: предпочтительно `Ctrl+`` и `Cmd+`` на macOS, если
  framework/platform не требует ближайшей совместимой комбинации.

## Auto Open

- В Settings / Diagnostics находится `Git Console / Auto open` со значениями
  `On errors`, `Always`, `Never`; default — `On errors`.
- `On errors` автоматически открывает console и выбирает failed User command.
- `Always` открывает console при старте User command.
- `Never` никогда не открывает console автоматически.
- Internal commands сами по себе не раскрывают panel.

## Durable Architecture And Constraints

- Git execution layer не зависит от Presentation. Git invocations публикуют
  incremental activity через application-level abstraction; Presentation
  подписывается на observable session history.
- Runtime updates применяются incrementally. Обычный Started/Output/final event не
  должен требовать полного snapshot/rebuild списка или пересоздания неизменившихся
  presentation items. Полная reconciliation допустима при открытии console, смене
  фильтра и других редких явных resync scenarios.
- Сбор activity централизован в общем Git process execution path. Сервисы, которым
  требуется captured result или streamed-to-file output, используют тот же runner
  и тот же activity sink вместо отдельного UI-specific logging.
- stdout и stderr читаются независимо и параллельно до EOF, включая cancellation
  drain. Ограничение console history не изменяет полноту machine-readable
  `GitCommandResult` и не должно нарушать binary-safe streamed-to-file paths.
- `GitCommandActivity`, Git Console history и Git/Application results сохраняют
  captured textual stdout/stderr в существующем representation: UTF-8 decoding,
  trimming, truncation marker и streamed-to-file semantics не меняются ради UI.
- На Presentation boundary `NUL` (`U+0000`) отображается как `\\0`; остальные
  UI-unsafe `char.IsControl` characters, кроме структурных `\r`, `\n`, `\t`, — как
  uppercase `\\xNN` (или `\\uXXXX` для code unit выше `U+00FF`). Printable Unicode
  остаётся неизменным. Git Console сохраняет существующую `\r` progress semantics.
- `Copy all` использует ту же policy для unsafe controls в stdout/stderr, но сохраняет
  настоящие `\r`, `\n` и `\t`; clipboard payload не должен содержать literal NUL или
  другие UI-unsafe machine-readable delimiters.
- Для одной command сохраняется не более 1 MiB raw stdout и 1 MiB raw stderr;
  ограничение применяется непосредственно во время streaming. Превышение явно
  маркируется `[output truncated]`, marker появляется один раз, а process pipe всё
  равно продолжает читаться до EOF.
- Presentation агрегирует интенсивный live output и обновляет visual controls
  incrementally, чтобы process chunks не создавали по UI-dispatch/update на каждый
  маленький fragment.
- Когда Git Console закрыта, history/status/auto-open продолжают работать, но её
  list/details controls не получают live visual updates и live-duration timer не
  работает. При открытии выполняется один актуальный snapshot, после чего console
  снова переходит на incremental updates.
- Internal commands, невидимые при фильтре `User commands`, не должны визуально
  менять console. Исключение: Internal command может точечно удалить visible User
  entry, если именно она была вытеснена глобальным history limit.
- Existing application-level Git error messages сохраняются. Git Console является
  дополнительным diagnostic source и не заменяет понятные ошибки пользователя.
- Existing OperationBanner для merge/rebase/conflicts сохраняет независимую роль:
  он управляет active Git operation, а Console только показывает invocations/output.
- Environment variables Git process не отображаются и не сохраняются в Console.
- Sensitive command-line data (credentials, tokens, passwords, authorization data)
  маскируются до попадания в history/display/copy surfaces.
- History существует только в памяти процесса и очищается при завершении CSharpGit.

## Non-Goals

- Интерактивный terminal или shell prompt.
- Произвольный ввод Git commands.
- Полноценный terminal emulator или ANSI/VT rendering.
- Повторный запуск сохранённой command.
- Persistence history между sessions.
- Настраиваемый или неограниченный history limit.
- Объединение stdout и stderr в один глобально ordered stream.
- Замена OperationBanner или существующей application error handling.

## Acceptance Criteria

- Все Git CLI process paths регистрируют Started, incremental output и final state
  через общий activity mechanism; независимых обходных process paths для обычных
  Git invocations нет.
- History никогда не превышает 100 entries и поддерживает User/All filtering.
- Entry содержит started/completed timestamps, duration, directory, executable,
  arguments/display command, kind, status, exit code, stdout и stderr.
- Failed и cancelled commands сохраняют уже полученные diagnostic data и корректный
  status.
- stdout/stderr видны до завершения долгой command; оба stream читаются параллельно
  без pipe deadlock.
- Entry сохраняет presentation identity от Running до final state; runtime events
  не вызывают full list rebuild.
- Manual selection стабилен при activity/output других commands.
- Visual selection, selected activity и details всегда согласованы; после rebuild
  selection сохраняется по activity id, а при отсутствии этой activity выбирается
  первый доступный visible entry или empty state для пустого списка.
- Git progress с `\r` отображается как изменяющаяся текущая logical line.
- Supported User operations получают diagnostic progress при redirected stderr,
  если это не конфликтует с явно заданными progress/quiet options.
- Закрытая console не обновляет свои visual controls и не держит live-duration
  timer; открытие показывает накопленный output и продолжает live streaming.
- Command formatting корректно quotes arguments с spaces и пригодно для copy.
- Secrets в поддерживаемых URL/options/authorization forms маскируются.
- stdout/stderr truncation ограничивает history memory во время streaming, остаётся
  UTF-8 safe и явно виден пользователю ровно одним marker.
- Machine-readable command result не ограничивается console history limit;
  streamed-to-file output остаётся binary-safe.
- Git Console не передаёт literal NUL и другие UI-unsafe control delimiters из
  captured stdout/stderr непосредственно в XAML `TextBox`; escaping одинаково
  работает для full reset/resync и incremental streaming.
- `NUL` отображается как `\\0`, остальные unsafe control characters — deterministic
  uppercase hex escapes; printable non-ASCII Unicode, newline и tab сохраняются, а
  carriage return продолжает использовать progress-line semantics.
- `Copy all` применяет ту же unsafe-control policy к stdout/stderr, не модифицируя
  captured activity state.
- Status bar, manual open/close, auto-open modes, copy actions и empty state работают
  независимо от OperationBanner.
- Existing tests продолжают проходить; новые tests покрывают streaming history,
  bounded buffers, carriage-return display, progress policy, executor streaming,
  cancellation, binary output и incremental presentation state.
