# IDD-0012.spec-repository-tree-navigation

## Intent

Repository Tree должен оставаться компактной и предсказуемой навигацией по refs даже в repository с большим количеством именованных веток.

Спецификация уточняет presentation semantics дерева веток поверх IDD-0010 и не меняет Git model или ref semantics из IDD-0006.

## Related Specifications

- IDD-0006
- IDD-0010

## Branch hierarchy and ordering

Local и remote branch names, содержащие `/`, отображаются иерархически как branch folders.

На каждом уровне branch hierarchy порядок одинаков:

1. непосредственные branch leaves без следующего path segment;
2. затем branch folders;
3. внутри каждой группы элементы сортируются по имени без учета регистра.

Current local branch не меняет позицию в сортировке. Она визуально выделяется жирным начертанием имени без отдельной галочки или current-branch icon.

То же правило рекурсивно применяется внутри branch folders и для remote branch hierarchy.

## Default branch marker

Remote default branch и local branch, которая действительно tracks эту remote
branch, отмечаются одинаковой метафорой home icon. Иконки визуально различаются:
remote marker использует accent style/color, local marker — отдельный нейтральный
style/color.

Default marker является дополнительным индикатором и не заменяет bold emphasis
current branch, branch type, selection или ahead/behind state. Совпадение имени
local branch с remote default branch само по себе не создает marker.

Если default branch неизвестна, home marker не отображается.

## Initial expansion

После первого построения Repository Tree для repository:

- `Branches` раскрыт;
- путь branch folders до current local branch раскрыт, чтобы current branch была видима;
- `Remotes` свернут;
- отдельные remote nodes свернуты;
- `Tags` и `Stashes` свернуты.

Если current branch находится непосредственно под `Branches`, дополнительные branch folders автоматически не раскрываются.

## Expansion state during the session

Ручное expand/collapse является пользовательским presentation state и сохраняется при последующих rebuild/refresh Repository Tree в рамках открытого repository.

Refresh repository state, изменения working tree, обновление refs и другие причины пересоздания presentation nodes не должны самопроизвольно возвращать дерево к начальному состоянию.

При переключении current local branch путь до новой current branch автоматически раскрывается, даже если соответствующие folders ранее были свернуты. После этого последующие refresh снова сохраняют пользовательское состояние.

При открытии другого repository expansion state сбрасывается и применяется initial expansion policy нового repository.

## Architecture

Expansion state принадлежит presentation layer и не является частью Git/domain state.

Stable expansion identity должна различать как минимум:

- root groups;
- remotes;
- local branch folders по полному branch path;
- remote branch folders с учетом remote и полного branch path.

Presentation rebuild может создавать новые `RepositoryTreeNode`, но должен восстанавливать expansion state по stable identity.

## Acceptance Criteria

- На любом уровне branch leaves отображаются раньше branch folders.
- Branch leaves сортируются alphabetically case-insensitive.
- Branch folders сортируются alphabetically case-insensitive.
- Current branch emphasis не влияет на порядок.
- Current local branch отображается жирным начертанием имени и не имеет отдельной галочки/current icon.
- Remote default branch имеет home marker remote style/color.
- Tracking local counterpart remote default branch имеет home marker другого
  style/color; local branch с несовпадающим upstream marker не получает.
- Default marker сосуществует с bold current-branch emphasis, selection, ahead/behind и branch
  tree behavior без изменения их semantics.
- `Branches` initially expanded и current branch path видим.
- `Remotes`, remote nodes, `Tags` и `Stashes` initially collapsed.
- Ручное раскрытие или сворачивание сохраняется после repository refresh/rebuild.
- Переключение current branch раскрывает путь до новой current branch.
- Открытие другого repository не наследует expansion state предыдущего repository.
- Local и remote branches остаются Git-semantically неизменными; меняется только presentation behavior.

## Verification

Проверять как минимум repository с:

- root branches `main`, `develop`;
- folders `feature/*`, `bugfix/*`;
- nested branch `feature/backend/api`;
- несколькими remotes;
- current branch внутри nested folder;
- remote default branch и tracking/non-tracking local branches.

Проверить начальное состояние, ручной expand/collapse с последующим Refresh, switch между root/nested current branches, жирное выделение current branch без галочки и отображение local/remote default markers.
