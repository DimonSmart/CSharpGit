# IDD-0016.spec-repository-images

## Intent

Карточки `Recent repositories` помогают визуально различать репозитории с помощью
локального логотипа или публичного repository preview, не увеличивая perceived
startup time и не превращая CSharpGit в GitHub-specific client. Квадратная иконка
и широкая preview-картинка являются разными visual assets и не должны
взаимозаменяться автоматически.

## Behavior

- Карточка recent repository сначала использует уже доступный persistent cache;
  при отсутствии подходящего visual asset сразу показывает существующий generic
  repository icon.
- Repository visual asset классифицируется как `Icon` или `Preview`.
- Локальные кандидаты `.github/repository-icon.*`, `.github/logo.*`,
  `docs/logo.*`, `logo.*`, `icon.*` считаются `Icon` и имеют приоритет над
  remote asset.
- Для public GitHub repository `og:image`/Social Preview считается `Preview`, а
  не `Icon`.
- `Icon` занимает одну базовую ячейку: изображение около 56 × 56 DIP в
  нейтральной media-области около 72 × 72 DIP слева от текста.
- Декодированный `Preview` в сетке шириной от двух колонок занимает ровно две
  базовые ячейки. Preview — слева, вплотную к левому, верхнему и нижнему краям
  скруглённой карточки: без отдельной визуальной рамки, media backdrop и
  внутренних отступов. Название, путь, metadata и независимые Pin/Remove —
  справа; кнопки — в верхнем правом углу текстовой области.
- Высота Wide Preview равна высоте видимой карточки (обычно около 112 DIP).
  Ширина рассчитывается по фактическому aspect ratio декодированного BitmapImage,
  а не задаётся фиксированной пустой широкой рамкой: для 1200×630 это примерно
  213 DIP при высоте 112 DIP. При более широких изображениях действуют предел
  360 DIP по изображению и резерв минимум 236 DIP под текстовую часть,
  включая её внутренние отступы; `Stretch=Uniform` не обрезает и не искажает
  изображение. Только внешняя форма карточки может скруглять углы.
- Compact Icon/glyph продолжает использовать прежний нейтральный media backdrop
  и отступы. У одноколоночного Compact Preview сохраняется адаптивный slot;
  переход Compact ↔ Wide не требует изменения persisted state.
- При одной колонке `Preview` занимает одну ячейку и пропорционально
  отображается рядом с текстом в media slot шириной 72–96 DIP, не вытесняя
  элементы управления. Производная квадратная icon-картинка не создается.
- Пока пригодность image candidate не подтверждена декодированием,
  карточка показывает glyph (либо прежний успешно декодированный asset)
  и не резервирует новые колонки. Расположение зависит от текущего
  отображаемого ресурса, а не от пути/extension/URL.
- Если asset отсутствует или не декодируется, показывается generic repository
  glyph в том же зарезервированном slot.
- `Preview` сохраняется в cache как отдельный visual kind и может повторно
  использоваться без network request.
- Поиск изображения выполняется после построения start screen и не блокирует UI.
- Поддерживаются как минимум PNG, JPEG/JPG и WebP. Поврежденное или слишком
  большое изображение безопасно игнорируется.
- Для public GitHub repository без локального изображения может использоваться
  `og:image`/Social Preview, полученный из публичной metadata repository page.
  `https`, SCP-style SSH и `ssh://` GitHub remotes распознаются.
- Remote requests выполняются асинхронно с ограниченным параллелизмом. Для
  repository без remote URL сеть не используется.
- Remote cache имеет TTL 7 days и использует stale-while-revalidate: stale
  preview остается доступным немедленно и заменяется только после успешного
  refresh.
- Отрицательный результат кешируется примерно на 24 hours; появление или
  изменение local candidate инвалидирует negative cache независимо от TTL.
- Если repository folder удалена, уже cached visual asset может продолжать
  отображаться вместе с существующим состоянием `Folder not found`.
- Ошибки image resolving/cache/network являются non-critical: UI остается
  работоспособным и использует generic icon без dialog/toast.

## Durable Architecture And Constraints

- `RecentRepositorySettings` не содержит image state. Repository image является
  производным visual resource.
- Presentation зависит от repository-image abstraction; filesystem/cache/hosting
  providers находятся за этой границей. `RecentRepositoriesViewModel` не
  содержит GitHub-specific network logic.
- Граница repository-image abstraction явно сообщает visual kind (`Icon` или
  `Preview`), поэтому presentation не выводит тип asset из размеров файла, URL
  или hosting provider.
- `RepositoryImageKind` определяет тип ресурса; только готовый `Preview`
  меняет column span контейнера `GridViewItem` (2 при 2+ колонках).
  `Icon` и fallback glyph всегда имеют span 1. Число колонок и конечные
  размеры назначает presentation, а не ViewModel/settings; тип не выводится
  из aspect ratio, расширения или hosting URL.
- `BitmapImage` перед публикацией как готового image state подтверждает
  декодирование через `ImageOpened`/`ImageFailed` исходного объекта.
  Pending-кандидат живёт в не-Collapsed visual tree; поздние callbacks
  отклоняются по идентичности bitmap, а старый asset сохраняется при refresh.
  При recycle `GridViewItem` снимает подписки с прежнего item и сбрасывает
  span 1. Resize никогда не запускает image resolve/Git/FS I/O.
- Hosting-specific providers расширяемы без изменения ViewModel/UI; первая
  remote implementation поддерживает GitHub, а GitLab/Gitea/Forgejo могут быть
  добавлены позже.
- Cache хранится в application data/cache CSharpGit, а не в Git repository.
  Identity предпочитает canonical remote URL, иначе normalized local path.
- Local cache валидируется как минимум по source path, size и
  `LastWriteTimeUtc`.
- Cache ограничен примерно 50 MB и удаляет давно не использованные image files.
  Remote image download ограничен 5 MB.
- Один и тот же repository image resolve не запускается конкурентно несколько
  раз в одном процессе.
- Обновление visual одной карточки выполняется через property notification и не
  пересоздает всю коллекцию `Recent repositories`.

## Non-Goals

- Автоматическое преобразование Social Preview в квадратную иконку.
- Увеличение высоты preview-card относительно обычной карточки.
- GitHub authentication и private repository images.
- Remote image providers для GitLab, Gitea, Forgejo и других hosts в первой
  реализации.
- Recursive image search по repository tree.
- Пользовательские уведомления об image-loading errors.

## Acceptance Criteria

- Local icon отображается на карточке вместо generic icon и имеет приоритет над
  GitHub Social Preview.
- GitHub `og:image` классифицируется как `Preview` и не отображается в квадратном
  icon slot карточки.
- `Icon` и glyph остаются Compact со span 1; Icon около 56 DIP без искажения.
- Успешно декодированный `Preview` переключает конкретный item в Wide
  Preview (span 2 при 2+ колонках) либо Compact Preview (span 1 при одной).
- Wide Preview отображается слева без вложенной рамки и внутренних полей,
  занимает максимальную доступную высоту около 112 DIP и сохраняет `Uniform`.
  Кнопки Pin/Remove находятся вверху справа, в текстовой области.
- Decode failure возвращает glyph + span 1, если прежнего годного изображения
  не было; failed refresh не сбрасывает уже готовое изображение.
- Async decode не меняет persisted order и не затрагивает другие контейнеры;
  recycling и поздний callback не могут выставить устаревший span.
- `Icon`/`Preview` classification доступна presentation через repository-image
  abstraction, без GitHub-specific logic в ViewModel.
- Repository без доступной картинки сохраняет существующий fallback UI.
- Start screen становится доступен до filesystem/network image resolving.
- Fresh persistent cache отображается без network request; stale remote cache
  остается доступным во время background refresh.
- Изменение local image приводит к обновлению cache.
- Failed background refresh не удаляет ранее cached remote preview.
- Negative cache предотвращает повторные GitHub requests, пока он валиден.
- Windows и macOS используют один architecture path и не получают
  platform-specific GitHub logic.
- Открытие и удаление recent repositories сохраняют прежнее поведение.

## Verification

- Unit tests покрывают local candidate priority, invalid image, cache hit,
  local invalidation, remote TTL/stale refresh, negative cache, удаленную
  repository folder и поддерживаемые GitHub remote formats.
- Unit tests отдельно проверяют classification локального asset как `Icon` и
  GitHub `og:image` как `Preview`.
- Start-screen contract tests проверяют границу abstraction/provider/UI,
  asynchronous candidate decode, выбор 1/2-column span по готовности Preview,
  прозрачное пропорциональное изображение, fallback, stale-cache refresh и
  per-container subscriptions. Геометрические tests покрывают resize и thresholds.
- Unit/contract tests проверяют пропорциональную ширину Wide Preview при
  1200×630, 16:9, square и ultrawide, резерв под текст, отсутствие media
  backdrop и padding у Wide, привязку действий к правому блоку и очистку
  подписок при recycle/unload.
- Runtime smoke на Windows/macOS Skia проверяет видимое примыкание Preview к
  краям карточки, скругление внешнего левого края, длинные названия, hover/
  focus/DnD, recycle, масштабирование, темы и большие списки; непроверенную
  ОС нельзя считать подтверждённой.
- Полный релевантный test suite запускается после реализации.
