# IDD-0025.spec-reflog-in-history

## Intent

History может по явному переключателю расширять обычную `All references` историю commits,
достижимыми через Git reflog, чтобы пользователь мог находить и восстанавливать commits после
reset/rebase/delete-ref без отдельного reflog viewer и без изменения обычного commit-action flow.

## Behavior

- В compact History toolbar один взаимоисключающий selector с тремя presentation-состояниями:
  `Current`, `All`, `+ Reflog`.
- `Current` означает существующую `Current branch` history без reflog.
- `All` означает существующую `All references` history без reflog.
- `+ Reflog` означает обычную `All references` history плюс reflog roots, семантически эквивалентно
  `git log --all --reflog` с существующими ordering/filter/pagination options.
- Selector не вводит третий domain `HistoryScope`: `+ Reflog` остаётся комбинацией
  `All references` scope и существующего reflog option.
- Состояние reflog option сохраняется через application settings; старые settings без поля трактуются
  как Off, то есть selector показывает обычный `All` при стандартном all-references scope.
- Выбор `Current` или `All` выключает reflog mode; explicit ref-scoped history также выключает
  reflog mode.
- Repository Tree navigation к обычной ref остаётся навигацией внутри общей History и сохраняет
  активный reflog option; отдельный `Show branch history only` остаётся ref-scoped operation.
- Commit, Changes, Files и существующие commit actions работают для reflog-only row по тому же
  full commit hash и тем же eligibility/confirmation rules.
- Selection при reload сохраняется по full hash, если commit остаётся visible; иначе применяется
  обычный fallback и stale details исчезают.

## Git Semantics

- Git CLI является authoritative source revision/reachability semantics.
- Не используются `git log -g`, `--walk-reflogs` и ручное чтение `.git/logs`.
- `Reflog-only` означает commit, достижимый через reflog, но не достижимый из обычной `--all`
  semantics; classification выполняется Git-native batch query, эквивалентной
  `git rev-list --reflog --not --all`.
- Один commit отображается один раз независимо от количества reflogs, в которых он встречается.
- Commit, одновременно normal-reachable и reflog-reachable, не считается reflog-only.
- После mutation/refresh reachability вычисляется заново; создание normal ref на recovered commit
  оставляет commit visible, но снимает reflog-only classification.

## Architecture And Performance

- Reflog является option существующего History query pipeline; отдельного ReflogHistoryService нет.
- `IsReflogOnly` передаётся Presentation как semantic history state. Presentation не определяет
  reachability, не сравнивает decorations и не добавляет fake `reflog` в `Commit.References`.
- Classification выполняется batch operation; per-row Git processes запрещены.
- Existing incremental loading, filtering, topology, cancellation/generation protection и
  navigation-through-commit сохраняются и используют одинаковые revision roots/options.
- Reflog mode не требует eager materialization full commit metadata или reflog event metadata.
- Settings persistence идёт через `IAppSettingsService`; старые settings без поля трактуются как Off.

## Presentation

- History scope/reflog selector использует стандартный platform control, а не собственную имитацию
  segmented control; подписи компактные: `Current`, `All`, `+ Reflog`.
- Reflog-only row имеет лёгкий отличающийся background и компактный `reflog` badge возле subject/refs.
- Tooltip объясняет, что commit недостижим из normal refs и доступен через Git reflog.
- Badge не является Git ref; graph lines остаются непрерывными, а selected/hover/focus states визуально
  сильнее reflog background.

## Non-Goals

- Reflog event viewer (`HEAD@{n}`, operation message, actor/time metadata).
- `reflog expire`, GC recovery или собственная recovery database.
- Reflog-specific commit actions.
- Новый commit graph algorithm или pixel-perfect GitExtensions copy.

## Verification

- Real-repository integration test: `A -> B -> C`, reset to B, normal history hides C, reflog history
  shows C as reflog-only; branch at C + refresh keeps C and clears `IsReflogOnly`.
- Tests cover union semantics, filtering, Current branch isolation, deduplication, setting persistence
  and legacy defaults.
- UI contract verifies one three-state selector, semantic badge/background/tooltip and absence of fake
  ref logic.
- Existing History, graph, Repository Tree, Changes/Files, settings and commit-action tests remain green.
