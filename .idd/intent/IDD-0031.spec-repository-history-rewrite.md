# Remove Repository Path from Local History

## Intent

CSharpGit lets the user remove one exact repository-relative regular-file path from all reachable local Git history while preserving repository topology and remote configuration. The operation is deliberately local, destructive, explicit, and recoverable through an independently verified mirror backup.

## Behavior

- A regular file selected in the historical `Files` tree or an equivalent Content Search result exposes `Remove from repository history…`.
- The path is taken directly from the historical `RepositorySnapshotEntry.Path`; directories, symlinks, submodules and unsupported entries are not eligible.
- Before confirmation CSharpGit checks that `git-filter-repo` is available, validates the repository state and analyzes path-history commit count plus affected local branches, tags and remote-tracking branches.
- Confirmation always explains that history and commit hashes will change, signed commits/tags can lose signatures, a safety backup will be created, remote repositories are not changed, and exposed credentials must be revoked or rotated independently of history rewriting.
- The operation removes only the selected exact path. Rename history and previous names are not followed.
- The rewrite uses `git filter-repo --force --partial --prune-empty never --invert-paths --path <path>`. Every path argument is passed as one literal process argument through the shared Git command executor.
- No push, force-push, fetch, pull or remote-server mutation is performed by this workflow.

## Safety Preconditions

Rewrite is blocked for bare, shallow or partial/promisor repositories; linked/non-primary worktrees; additional linked worktrees; detached HEAD; active merge/rebase/cherry-pick/revert/bisect; dirty index or working tree; untracked files; stashes; or `refs/replace/*`.

A source fingerprint records HEAD symbolic/object identity, the ref set/object IDs, operation state and clean state. The full preflight and fingerprint are repeated after backup creation. If the repository changed meanwhile, filtering does not start.

## Backup and Topology Preservation

Before the destructive phase CSharpGit creates an independent persistent mirror using `git clone --mirror --no-local` in a persistent location that is verified to be outside both the repository and its Git directory, then verifies the source refs against the backup.

The operation snapshots and later verifies:

- names of `refs/heads/*`, `refs/tags/*` and `refs/remotes/*`;
- symbolic-ref topology;
- remote URLs/push URLs/fetch refspecs and branch upstream configuration.

Unexpected topology/configuration changes are failures; the application does not conceal them by synthesizing replacement branches.

## Verification and Cleanup

After filtering and before cleanup, every surviving relevant ref is checked with Git to ensure the selected path is no longer reachable. Only after this reference-level verification does CSharpGit expire reflogs and prune unreachable old objects.

Final verification repeats topology/configuration and path checks, validates a clean readable repository, and obtains the actual rewritten-commit count from `.git/filter-repo/commit-map` where old and new object IDs differ.

After `git filter-repo` begins, ordinary UI cancellation is not propagated to the process. Other CSharpGit mutations and repository close are blocked until the operation completes. Automatic rollback is not attempted; any post-boundary failure shows the safety-backup path and refreshes from the repository's actual on-disk state.

## Refresh

History rewrite uses the existing global repository mutation coordination. Before execution, stale history/diff/Files snapshot/search/preview generations and SHA-keyed caches are invalidated.

Post-operation refresh preserves the existing `Repository` object, rereads repository state and history without reopening it, selects the rewritten current HEAD, reloads Files only when active, and acknowledges internally generated repository-change notifications. This refresh is local-only: it may use a cached/local remote HEAD ref but must not fall back to `ls-remote` or otherwise contact a remote server.

## Non-Goals

- rename tracking or deletion by blob ID;
- secret-value rewriting or automatic secret detection;
- directory removal;
- automatic publishing of rewritten history;
- server-side PR/fork cleanup;
- handling other clones;
- automatic installation of Python, pip or `git-filter-repo`;
- automatic rollback or signature re-signing.

## Verification

Automated coverage includes path validation, clean/dirty preflight, exact path removal with spaces/Unicode, branch/tag/remote-tracking namespace preservation, remote/upstream configuration preservation, rewritten commit-map counting, UI warnings, shared mutation coordination, stale presentation invalidation and close blocking. Tests requiring `git-filter-repo` remain harmless on developer machines where the tool is unavailable.
