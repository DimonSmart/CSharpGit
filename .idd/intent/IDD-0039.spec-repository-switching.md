# IDD-0039 — Repository switching and close lifecycle

## Status

Current product intent.

## Intent

CSharpGit supports exactly one active repository workspace at a time and allows the user to leave it without restarting the application.

The workspace lifecycle is:

```text
no repository
    ↓ open
Repository A
    ↓ switch
Repository B
    ↓ close
no repository
```

Multiple simultaneously open repositories, repository tabs, and workspace sessions are outside this intent.

## Repository selector

When a repository is open, the main toolbar exposes a compact `Current repository` dropdown instead of a passive path label.

The selector:

- always shows the current repository first;
- shows up to 8 other repositories;
- uses the existing recent-repository projection order: pinned by `PinnedOrder`, then unpinned by `LastOpenedUtc`;
- excludes the current repository using normalized, platform-aware path comparison;
- provides `Open repository…`, `Create repository…`, `Repositories…`, and `Close repository`;
- keeps full paths available through compact secondary text and/or tooltip;
- is a quick switcher, not a replacement for the full repository launcher.

The current repository remains representable even when it is not present in persisted recent-repository settings.

## Common path-based switch

Folder picker, recent repository, quick selector entry, and newly created working repository converge on one path-based repository-opening workflow.

The folder picker is only responsible for producing a path. It is not the repository-switch operation.

Selecting the already active repository is a no-op.

An unavailable recent repository does not replace the current workspace and produces a clear user-facing message.

## Commit draft protection

The commit message is transient workspace state and must be protected whenever the current repository would be left.

Switching or closing with an unapplied commit message requires explicit confirmation.

For a switch:

```text
confirm discard
→ try open target repository
→ initial target refresh succeeds
→ discard old draft
```

If opening or initial refresh fails, the previous repository remains active and its commit draft remains unchanged.

For close, the draft is discarded only after the close operation is accepted.

Staged and unstaged working-tree changes do not require confirmation because switching/closing does not reset, checkout, unstage, or otherwise modify the previous repository.

## Close semantics

Closing a repository:

- invalidates repository-owned asynchronous loads;
- cancels existing cancellation-aware work where available;
- clears repository-specific presentation state;
- sets the active repository to `null`;
- leaves recent-repository history intact;
- lets existing repository-change subscribers stop monitoring and return the UI to the existing launcher.

The launcher remains the existing start-screen state: recent repositories when present, otherwise the empty start screen.

## Failure and stale-result guarantees

A repository switch must not set the active repository to `null` as an intermediate step.

If target initialization fails, the previous repository is restored.

Repository-specific asynchronous results from an old repository must never publish into a new repository or into the launcher after close. Existing cancellation tokens, generation counters, reference identity checks, and preview publication gates remain the required mechanism.

Repository monitoring follows the active repository and stops when the active repository becomes `null`.

## Concurrency

Unsafe Git mutation and repository switching are mutually exclusive.

A second repository switch cannot start while a switch is already in progress.

Read/refresh work that is already stale-safe or cancellation-safe does not by itself block repository switching merely because the global busy indicator is active.

No artificial delays are used to wait for background work.

## Other entry points

The open-workspace application menu exposes:

- `Open repository…`;
- `Create repository…`;
- `Repositories…`;
- `Close repository`.

`Ctrl+O` opens the repository folder picker both from the launcher and from an active workspace, then follows the same common switch workflow.

`Repositories…` and `Close repository` share the same internal close lifecycle; they differ only in user-facing intent.

## Non-goals

This intent does not add:

- multi-repository tabs;
- multiple live workspaces;
- open-in-new-window behavior;
- a new navigation framework;
- a new recent-repository store;
- a second repository-monitoring subsystem;
- a full repository manager inside the toolbar flyout.
