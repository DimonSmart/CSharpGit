# IDD-0021.spec-branch-deletion

## Intent

Пользователь безопасно удаляет local и remote branches из Repository Tree с явным
подтверждением, стандартной Git semantics и предсказуемым поведением при частичном
успехе. Local deletion остаётся safe-by-default, но пользователь может явно выбрать
force deletion для конкретной операции в local confirmation dialog или в
combined remote/local deletion dialog. Combined deletion симметрична: remote
deletion может дополнительно удалить local branch, а local deletion может
дополнительно удалить однозначно соответствующую remote branch.

## Behavior

- `Delete` для local branch всегда открывает confirmation dialog. Current local
  branch и branch, используемую существующим worktree, удалить через этот action
  нельзя; существующие busy/mutation restrictions сохраняются.
- Local confirmation содержит выключенный по умолчанию checkbox
  `Force delete even if the branch is not fully merged`. Checkbox создаётся заново
  для каждой операции и не сохраняется в ViewModel, settings или session state.
- Под Force option отображается предупреждение, что force deletion может удалить
  единственную branch reference на commits и усложнить их восстановление; UI не
  утверждает, что commits немедленно физически удаляются из repository.
- Без Force local branch удаляется стандартным `git branch --delete`.
- После явного включения Force local branch удаляется через
  `git branch --delete --force`.
- Git остаётся source of truth для merge safety. Приложение не вычисляет
  merged/unmerged state или reachability commits, не парсит Git error для выбора
  режима и не повторяет неудачный safe delete автоматически как force delete.
- Force option не делает current/worktree-owned branch доступной для `Delete`, не
  выполняет checkout/detach HEAD и не изменяет или удаляет worktrees.
- `Delete` для remote branch всегда открывает confirmation dialog и удаляет branch
  через deletion refspec `git push <remote> :refs/heads/<branch>`. Удаление самой
  remote branch не получает Force semantics; Force option относится только к явно
  выбранному дополнительному удалению соответствующей local branch.
- Remote deletion идемпотентна относительно уже отсутствующей server branch:
  deletion refspec считается Git успешным и в этом случае, поэтому отдельная
  проверка через `ls-remote`, provider-specific parsing или ручной `update-ref`
  не нужны. Обычные authentication, transport, permission и remote-rejection
  failures по-прежнему остаются ошибками.
- Если найдена соответствующая local branch, confirmation remote deletion содержит
  выключенный по умолчанию checkbox для её дополнительного удаления и отдельный
  выключенный по умолчанию Force checkbox для local branch.
- Force checkbox дополнительного local deletion disabled, пока не выбран
  `Also delete local branch`. При снятии основного checkbox Force сбрасывается.
  Для current local branch оба действия удаления local branch недоступны.
- Corresponding local branch сначала определяется по `Upstream`, равному полному
  имени выбранной remote branch. При отсутствии tracking branch применяется
  fallback по имени branch без configured remote prefix.
- Remote определяется по списку configured remotes; имя branch не разбирается
  простым разделением по первому `/`. При совпадении нескольких prefixes выбирается
  наиболее длинный configured remote prefix.
- Если соответствующая local branch является current, remote branch по-прежнему
  можно удалить, но checkbox local deletion disabled и UI объясняет причину.
- При комбинированном удалении remote branch удаляется первой. Local branch
  удаляется только после успешного remote deletion. По умолчанию используется safe
  mode через `git branch --delete`; `git branch --delete --force` используется
  только после отдельного явного opt-in в этом же remote deletion dialog.
- Если remote deletion успешен, а выбранное local deletion отклонено Git, remote
  deletion не откатывается. Пользователь получает явное сообщение о partial success
  вместе с Git error.
- Ошибка remote deletion не запускает local deletion. Уже отсутствующая remote
  branch не считается ошибкой Git при deletion refspec, поэтому выбранное
  дополнительное local deletion в этом случае продолжается.
- После успешного или частично успешного удаления repository state обновляется
  существующим mutation/refresh механизмом. Если history был scoped к фактически
  удалённой branch, UI возвращается к `All references`.

### Symmetric combined deletion

- Для обоих направлений дополнительное действие требует отдельного opt-in,
  выключено по умолчанию, создаётся заново для каждого dialog и не сохраняется в
  settings, ViewModel или session state.
- Remote initiated workflow сохраняет порядок `remote → optional local`. Local
  initiated workflow использует порядок `local → optional remote`.
- Если для local branch можно безопасно и однозначно определить remote target,
  local confirmation показывает `Also delete remote branch '<remote>/<branch>'`.
  Этот checkbox независим от local Force option; remote deletion не получает Force.
- Local → remote target определяется в Application layer через
  `BranchDeletionResolver`. Configured upstream имеет приоритет и остаётся
  валидным target даже без remote-tracking ref, пока соответствующий remote
  configured. Upstream на unconfigured remote возвращает отсутствие target и не
  запускает fallback.
- Если upstream отсутствует, resolver рассматривает remote-tracking branches,
  разбирая каждую относительно configured remotes. Относительное branch name
  должно точно совпасть с local branch name. Используется longest configured
  remote prefix; `Split('/')`, `EndsWith` и автоматическое предпочтение
  `origin` не используются. Единственное совпадение даёт target, отсутствие или
  ambiguity — нет.
- Local-initiated combined deletion сначала выполняет local deletion. При local
  failure remote deletion не запускается. После successful local deletion remote
  удаляется существующим `IRepositorySyncService.DeleteRemoteBranchAsync`.
- Если remote deletion после successful local deletion завершилась обычной
  ошибкой, local deletion не откатывается; UI показывает explicit partial-success
  message с исходной Git error. `OperationCanceledException` продолжает обычный
  cancellation path и не маскируется под partial success.
- History scope меняется только для фактически удалённой ref: successful local
  deletion сбрасывает local scope даже при последующей remote failure; remote scope
  сбрасывается только после successful remote deletion.
- Already-absent remote branch использует существующую идемпотентную semantics
  deletion refspec без `ls-remote`, provider-specific parsing или отдельного
  network probe.

## Durable Architecture And Constraints

- Branch deletion использует `IReferenceService` и существующий
  `GitCliRepositoryService`; safe/force intent представлен strongly typed mode, а
  отдельный Git execution layer или отдельный force-delete service не создаётся.
- Safe и force deletion используют существующий mutation execution mechanism.
- Remote deletion использует существующую Git push/authentication infrastructure,
  credential helpers, SSH configuration и обработку Git errors. Идемпотентность
  already-absent branch обеспечивается самим Git deletion refspec, без отдельного
  probe к remote.
- Операции выполняются асинхронно и участвуют в существующем busy/mutation
  механизме, который блокирует конфликтующие mutations и refresh-ит repository.
- Приложение не переключает branch автоматически ради удаления.

## Non-Goals

- Bulk branch-folder deletion не определяется этой спецификацией; оно описано
  отдельно в IDD-0028.
- Изменение semantics удаления remote branches.
- Автоматическое определение merged/unmerged status.
- Анализ или preview commits, которые могут потерять branch reference.
- Undo или восстановление deleted branch по SHA/reflog.
- Автоматический checkout другой branch.
- Автоматическое изменение или удаление worktree ради удаления branch.
- Автоматический retry safe deletion как force deletion.
- Удаление tags или remotes.
- Собственная authentication система.
- Новый Git execution mechanism.
- Выбор remote из dropdown при ambiguity или автоматический выбор `origin`.
- Новый network probe перед remote deletion или изменение semantics
  `DeleteRemoteBranchAsync`.

## Acceptance Criteria

- Local delete confirmation содержит Force checkbox и предупреждение; checkbox
  выключен при каждом новом открытии dialog.
- Без Force local deletion использует `git branch --delete`; force deletion
  происходит только после явного opt-in и использует `git branch --delete --force`.
- Force не делает current или worktree-owned branch доступной для `Delete` и не
  ослабляет existing busy/mutation restrictions.
- Приложение не пытается самостоятельно определять merged status или потенциально
  unreachable commits; Git refusal сохраняет branch и проходит через existing error
  handling.
- Remote branch имеет confirmed `Delete` action без Force option и действительно
  удаляется deletion refspec; already absent remote branch также завершается
  успешно, а stale local remote-tracking ref не остаётся в repository state.
- Remote confirmation предлагает соответствующую local branch только когда она
  найдена; local-delete checkbox выключен по умолчанию и disabled для current branch.
  Force-local checkbox также выключен по умолчанию, активируется только после
  выбора local deletion и сбрасывается при его отмене.
- Tracking relationship имеет приоритет над name fallback, configured remote prefix
  корректно сохраняет branch names с несколькими `/`.
- Combined remote/local deletion удаляет remote первой; local удаляется safe по
  умолчанию и force только после отдельного явного opt-in, сохраняя existing
  partial-success semantics.
- После операции Repository Tree, refs, badges и history scope не содержат stale
  reference на удалённую branch.

- Local confirmation предлагает optional remote deletion только при безопасно и
  однозначно разрешённом target. Upstream имеет приоритет; stale upstream допустим
  для configured remote; unconfigured upstream не запускает name fallback.
- При отсутствии upstream local → remote fallback требует единственного
  remote-tracking match по относительному branch name. Ambiguity не приводит к
  автоматическому выбору remote.
- Local-initiated combined deletion выполняется строго `local → optional remote`.
  Failed local deletion предотвращает remote deletion; remote failure после
  successful local deletion не откатывает local и показывает partial-success
  message. Cancellation не преобразуется в Git failure.
- Remote names и branch names с несколькими `/` разбираются longest-prefix
  правилом configured remotes в обоих направлениях.
- Remote opt-in local deletion dialog не сохраняется между открытиями и не влияет
  на Safe/Force semantics local branch.

## Verification

- Git integration tests используют реальный local repository и bare remote и
  проверяют merged Safe deletion, refusal + сохранение unmerged branch в Safe/default
  mode, успешное Force deletion unmerged branch, remote deletion, stale
  remote-tracking refs, already absent remote branch, unrelated push failure и branch
  names с `/`.
- Application tests покрывают оба направления resolution: upstream-first,
  unique-name fallback, configured remote prefixes, stale/unconfigured upstream,
  ambiguity, отсутствие match и branch names с несколькими `/`.
- Desktop contract tests проверяют standalone и оба combined workflows: local Force
  checkbox, remote opt-in, Safe/Force independence, local-before-remote и
  remote-before-local ordering, cancellation filter, partial-success UI и history
  scope только для фактически удалённой ref.
