# IDD-0010.spec-history-first-main-workspace

## Intent

Главное окно CSharpGit воспринимается прежде всего как Git history browser с
интегрированными working tree и Git operations. История является основной
рабочей областью; навигация по состояниям и refs расположена слева; детали
выбранного commit находятся под history; редкие действия появляются только в
релевантном контексте.

Основной принцип layout:

> History first. Navigation on the left. Details below. Actions appear where
> they are relevant.

## Main Workspace

После открытия repository главное окно содержит:

1. compact top toolbar с repository/current branch, доступом к commit/working
   tree mode и частыми network/refresh actions;
2. Repository Tree слева;
3. history filter и commit history/graph как основную центральную область;
4. resizeable details area под history;
5. compact status bar снизу;
6. contextual operation/conflict area только во время соответствующей Git
   operation.

Не используются постоянно видимые dashboard-колонки для branches, remotes,
stash, merge, rebase и merge-tool configuration.

## Repository Tree

Repository Tree является presentation model поверх существующих repository
state/ref models и не становится authoritative Git model.

Минимальные узлы:

- `Branches` с local branches;
- `Remotes` → remote → remote branches;
- `Tags`;
- `Stashes`.

Working tree/commit navigation не является ref navigation и поэтому не
отображается узлом Repository Tree.

Current local branch явно выделена. Local и remote branches остаются различимыми
по положению и контексту дерева.

Выбор local branch, remote branch, tag или stash по умолчанию является навигацией
в общей `All references` history: приложение находит commit, на который указывает
ref, при необходимости догружает общий history prefix до этого commit и переводит
selection/viewport на соответствующую строку без checkout. Контекст общей topology
при этом сохраняется. Отдельный ref-scoped history остается доступным как явное
контекстное действие `Show branch history only` (или эквивалентное для другой ref).
Double click local branch выполняет Switch/Checkout.

Контекстные действия как минимум:

- local branch: Switch/Checkout, Create branch from here, Merge into current,
  Delete, Copy branch name;
- remote: Fetch;
- Remotes group: Fetch all;
- remote branch: Checkout as tracking branch, Copy branch name;
- tag: Checkout detached, Copy tag name;
- stash: Apply, Pop.

## History

History занимает большую часть доступной рабочей области и сохраняет incremental
loading.

Над history находится compact filter с search, scope/ref и refresh. `Ctrl+F`
переводит focus в search. `F5` обновляет repository state/history.

Каждая строка history компактно содержит:

- graph;
- commit subject;
- refs рядом с subject, без обязательной второй строки;
- author;
- date/time;
- short hash.

Хотя History использует общую compact row-density system, commit graph остаётся
визуально непрерывным через границы строк. Изменения density и styling History
обязаны сохранять эту непрерывность.

Refs отображаются компактными badges/labels. UI не зависит от фиксированного
набора ярких цветов.

Общий scope как минимум поддерживает `All references` и `Current branch`.
Обычный выбор конкретной ref в Repository Tree переключает presentation на
`All references` (если нужен другой scope), снимает несовместимый text filter,
обеспечивает наличие target commit в incrementally materialized общей history и
навигационно выделяет этот commit. Ref-scoped history включается только отдельным
явным действием и не меняет working branch.

## Commit Details

Commit details расположены под history и отделены horizontal splitter. Они не
занимают постоянную правую колонку.

Commit Details отвечают на три разные задачи и поэтому имеют три отдельные
поверхности:

- `Commit` — что это за commit: full message, author, date/time, full hash,
  parents и refs;
- `Changes` — что изменил этот commit: существующее changed-file tree и
  интегрированный diff, включая текущую textual/binary semantics;
- `Files` — что существовало в repository после выбранного commit: полный
  tracked snapshot его Git tree, включая файлы, не изменявшиеся этим commit.

`Changes` и `Files` намеренно не смешиваются. Unchanged files не добавляются в
`Changes`, а `Files` не строится из commit diff. Выбор между `Commit`, `Changes`
и `Files` не меняет selected history commit.

### Repository snapshot in Files

Authoritative source для `Files` — Git tree ровно выбранного commit. Working
copy, index, diff выбранного commit и diff parent commit не используются для
реконструкции snapshot. Git paths сохраняют case-sensitive identity.

Snapshot загружается лениво только при активации `Files`. При смене selected
commit, пока `Files` активен, загружается snapshot нового commit; при уходе с
`Files` нерелевантные tree/content requests отменяются. Результат async request
может быть опубликован только если всё ещё совпадают repository session,
selected commit, активная `Files` surface и request generation.

Flat semantic snapshot кэшируется в bounded session cache по repository identity
и commit hash. Presentation tree, expansion/selection и search state не являются
частью Git snapshot data и не должны превращаться в unbounded lifetime cache.
Открытие другого repository очищает repository-specific snapshot state.

Git layer получает snapshot одной recursive tree operation с NUL-safe parsing и
возвращает semantic entries с path, object type/id и mode. Presentation строит
directory hierarchy локально; directory nodes являются presentation-only.
Начальное дерево не раскрывает все каталоги. Path segment identity сравнивается
ordinal/case-sensitively; display sorting детерминированно показывает directories
перед leaves, затем сортирует names case-insensitively с ordinal tie-breaker.

### Files search

По умолчанию search mode — `Name`. Name search выполняется локально по уже
загруженному flat snapshot, обновляется сразу при вводе, не запускает Git process,
ищет case-insensitive substring по полному repository-relative path и сохраняет
в дереве только match-и и необходимые ancestor directories. Search-induced
expansion временная и не уничтожает normal expansion state.

`Content` search выполняется только по Enter для непустого query. Первая версия
использует literal case-insensitive historical search, исключает binary files и
не поддерживает regex/fuzzy options. Git invocation использует argument-list API;
query передаётся одним argument. Git exit code `1` означает успешный search без
matches, а не ошибку. Filename/result parsing остаётся NUL-safe и не определяет
path разделением по `:`. Results показываются отдельным flat/path-grouped list;
large result set может иметь явно обозначенный visible limit.

Смена selected commit отменяет старый Content search, очищает old-commit results
и не запускает предыдущий query автоматически.

### Historical file actions

Regular file в `Files` может быть открыт системным/default application либо
`Open in editor` через configured Git Editor semantic infrastructure. В обоих
случаях открывается exact blob выбранного commit, включая файл, который вообще
не изменялся этим commit; current working-tree file не подставляется.

Для arbitrary `(repository, commit, path)` Application/Git предоставляет
semantic file-version resolution, после чего используется существующая safe
historical snapshot materialization из IDD-0017. Presentation не строит raw
`git show`, `git cat-file`, `git ls-tree` или `git grep` command lines.

`Open` и `Open in editor` остаются разными действиями по IDD-0023: первое
использует desktop shell/default application, второе — configured Git Editor.
`Copy path` копирует точный repository-relative Git path.

Symlink и submodule/gitlink видимы как специальные leaf entries, но первая версия
не следует/не материализует symlink, не рекурсит submodule, не открывает их как
regular files и не включает в Content search. Для них доступен `Copy path`.
Unsupported Git entries могут оставаться видимыми без regular-file actions.

Если application-level File History navigation существует, `Files` может
передать в неё repository, repository-relative path и selected commit hash. Сам
File History не реализуется этой surface и fake/dead action не добавляется.

## Working Tree Mode

Кнопка `Commit (N)` в постоянной top toolbar переключает центральную область из
History mode в Working Tree mode. `N` показывает текущее количество working-tree
changes, используя тот же repository state, который заполняет Working Tree mode.

В Working Tree mode эта же toolbar-кнопка становится `Back to history` и
возвращает History mode. Отдельная кнопка возврата внутри Working Tree pane не
используется.

Working Tree mode отдельно показывает:

- unstaged changes;
- staged changes;
- contextual Stage/Discard/Unstage actions;
- compact commit area.

Один файл может одновременно присутствовать в staged и unstaged sections, если
его Git state это требует.

Commit semantics остаётся определённой IDD-0005: обычный Commit использует
только Git index, silent staging запрещён, а пустой index приводит к explicit
choice. `Ctrl+Enter` может инициировать Commit в Working Tree mode.

## Toolbar, Rare Operations And Appearance

Постоянная top toolbar ограничена наиболее частыми действиями:

- repository/current branch;
- `Commit (N)` / `Back to history` navigation toggle;
- Fetch;
- Pull;
- Push;
- Refresh;
- overflow.

Theme не занимает место на main toolbar; System/Light/Dark доступны через
Appearance UI.

Create branch, explicit push configuration, stash creation, merge, interactive
rebase и merge-tool configuration доступны через context menus, overflow/dialogs
или другой явный contextual UI, но не занимают постоянную площадь main workspace.

## Git Operation / Conflict Context

Если merge/rebase/другая поддерживаемая operation находится in progress,
появляется contextual panel с operation status, conflicts и релевантными
Continue/Abort/Skip/resolution actions.

При отсутствии operation этот panel скрыт. Merge-tool configuration не является
частью постоянного conflict panel и открывается отдельно.

## Status Bar

Compact status bar может показывать:

- current branch/detached state;
- ahead/behind;
- working tree change count;
- busy/ready/current operation state.

Статус должен быть кратким и не дублировать большие постоянные explanatory
messages.

## Layout And Keyboard

Минимальные resizeable boundaries:

- Repository Tree ↔ main area;
- History ↔ Commit Details.

Не допускается фиксированная большая высота основного блока, подобная прежним
`470 px`; layout адаптируется к размеру окна.

Минимальный keyboard UX:

- `Ctrl+F` — focus history filter;
- `F5` — refresh;
- `Enter` — открыть/активировать выбранный item где применимо; в Files/Content
  search Enter запускает explicit content search;
- `Esc` — закрыть/вернуться из contextual mode где применимо;
- `Ctrl+Enter` — Commit в Working Tree mode, если command доступна.

## Durable Architecture And Constraints

- Git business logic не переносится в XAML ради layout.
- Repository Tree имеет отдельную presentation model (`RepositoryTreeNode` или
  эквивалент) и строится из existing application/domain/Git state.
- Repository snapshot имеет отдельный Application semantic boundary; Git layer
  отвечает за Git commands/NUL-safe parsing, Presentation — за hierarchy,
  filtering, expansion/selection и result presentation.
- Snapshot loading использует одну recursive Git tree query на uncached commit и
  не запускает per-file Git process или eager content loading.
- Навигация к ref в общей history и optional ref-scoped history являются read-only Git operations и не требуют checkout.
- Для target commit вне текущего loaded prefix допускается быстрый lightweight поиск его позиции по hash с последующей загрузкой общего topology prefix до target плюс небольшой trailing context; не требуется последовательная загрузка страниц по 100 commits.
- Existing staging/commit/ref/workflow semantics сохраняются.
- Mutating operations остаются asynchronous и координируются существующим
  mutation workflow; read-only history/diff/snapshot загружается on demand.
- History остаётся incremental; выбранная ref также не требует полной загрузки
  истории перед первым render.
- Diff загружается только для выбранного commit/file в `Changes`.
- Snapshot/search/open operations не меняют HEAD, current branch, index или
  working tree и не выполняют checkout.
- Existing historical materialization сохраняет binary-safe bytes, external
  temporary storage, safe path handling, cleanup after failure/cancellation и
  best-effort read-only completed snapshots.
- System, Light и Dark используют существующий Fluent/System appearance approach.

## Non-Goals

- Новый graph algorithm.
- Hunk/line staging.
- Advanced history query language.
- Pixel-perfect копирование Git Extensions.
- Редактирование historical repository state или запись editor changes обратно
  в selected commit.
- Checkout/restore из `Files`.
- Directory history, blame или реализация File History как части этого change.
- Repository-wide indexed/semantic search.
- Fuzzy Name search, regex Content search и content-search option panels.
- Recursive submodule browsing.
- Opening symlinks as filesystem links.
- Diff rendering внутри `Files` tree.
- Comparing arbitrary two commits.
- Полная замена presentation architecture.

## Acceptance Criteria

- History является крупнейшей основной рабочей областью.
- Слева есть Repository Tree с Local Branches, Remotes/Remote Branches, Tags и
  Stashes; current branch явно обозначена; Working Tree не смешивается с refs в
  этом дереве.
- В top toolbar есть `Commit (N)`, где `N` отражает текущее количество changes;
  кнопка открывает Working Tree mode и в этом mode превращается в
  `Back to history`.
- Working Tree pane не содержит отдельную дублирующую кнопку возврата в History.
- Single click branch/ref сохраняет общий `All references` graph, при необходимости догружает его до target commit, выбирает этот commit и прокручивает его в viewport без checkout.
- Даже старая ref, target commit которой не входил в первоначально загруженный history prefix, остается доступной для навигации и не должна становиться disabled/grey только из-за lazy loading.
- Ref-only history доступна отдельным явным contextual action и не является default single-click behavior.
- History rows содержат graph, subject, refs, author, date/time и hash; refs не
  требуют отдельной второй строки.
- Commit details расположены под history и имеют distinct `Commit / Changes / Files` tabs.
- Existing `Changes` changed-file tree и integrated diff semantics сохранены.
- `Files` лениво показывает полный tracked snapshot ровно selected commit,
  включая unchanged files, и не derives его из commit diff или working tree.
- Snapshot cache bounded и keyed repository/commit; stale requests не могут
  публиковаться после tab/commit/repository change.
- Name search local/immediate/case-insensitive по full path и сохраняет required
  ancestors; Content search explicit-on-Enter, literal/case-insensitive,
  historical, binary-excluding и cancellable.
- Exact regular file из snapshot, включая unchanged file, открывается из
  selected-commit blob; `Open` использует system/default app, `Open in editor` —
  configured Git Editor.
- Symlinks/gitlinks видимы, но не открываются/materialize/search как regular files;
  `Copy path` сохраняет repository-relative Git path.
- Working Tree является отдельным mode и явно разделяет staged/unstaged states.
- Commit workflow не меняет semantics Git index и не выполняет implicit staging.
- Старые постоянные branch/remotes/stash/rebase dashboard blocks отсутствуют.
- Rare operations доступны через contextual menus/dialogs/overflow.
- Conflict UI существует только при соответствующей active Git operation.
- Repository Tree/main и History/details resizeable.
- System/Light/Dark работают через общий appearance mechanism.
- History/ref history загружается incrementally, UI остаётся responsive во время
  Git operations.
- Files loading/search/open не меняют HEAD, current branch, index или working tree.
- Large repository snapshot не запускает per-file Git commands и не eager-loads contents.
- Existing Git capabilities не теряются из-за нового layout.

## Verification

- Desktop UI check проверяет наличие и layout Repository Tree, History,
  `Commit / Changes / Files`, toolbar navigation в Working Tree mode, splitters,
  scrolling, theme switching, busy state и commit empty-index safety flow.
- Git integration tests проверяют `ls-tree` snapshot parsing, Unicode/space paths,
  case-sensitive path identity, literal/NUL-safe historical Content search,
  no-match semantics, arbitrary unchanged-file resolution/materialization и
  repository-safety invariants.
- Presentation regression tests проверяют hierarchy construction, directories-first
  deterministic sorting, full-path Name filtering с required ancestors и bounded
  LRU snapshot cache.
- Async/manual verification проверяет lazy loading, cache hit, cancellation,
  stale-result rejection, per-commit expansion/selection state, Content search
  reset after commit change и local error states.
- Ручная проверка выполняется на repository с local/remote branches, tags,
  stashes, staged+unstaged state, merge topology, textual/binary changes, symlink,
  submodule, renamed/deleted files и active conflict operation.

## Working Tree detail surface

Working Tree mode keeps the commit area at the bottom and presents a resizable workspace above it: staged/unstaged lists and their actions on the left, with the currently selected staged-or-unstaged compact diff on the right. Only one side of a file is visually selected at a time.
