# IDD-0040 — Repository cloning

## Status

Current product intent.

## Intent

CSharpGit can clone a remote Git repository into a local directory and then open
the resulting repository through the existing single-workspace switch lifecycle.

Cloning remains a native Git operation. CSharpGit does not implement a transport
protocol or provider-specific repository API.

## Git ownership

The application invokes installed Git through the existing `GitCommandExecutor`
with a user-visible `CloneRepository` activity. Repository source and target are
separate process arguments and are never assembled into a shell command.

The logical command is:

```text
git clone -- <repository-source> <target-directory>
```

HTTPS, SSH, SCP-like remotes, credentials, credential helpers, SSH agents and
other transport behavior belong to installed Git. CSharpGit does not add
GitHub/GitLab/Azure DevOps authentication or terminal credential prompting.

## Application boundaries

Repository cloning is represented by `IRepositoryCloneService`; repository
creation remains `IRepositoryCreationService` and repository opening/switching
remains the existing repository lifecycle.

A successful clone produces a local path and then calls the same path-based
switch used by Open/Create/Recent. The clone service itself does not record
Recent repositories and does not open a workspace.

## Default local target

Global settings contain a `Default repositories folder`. Its platform default
is `<user-home>/source/repos`; legacy settings without the value and invalid
persisted values fall back to that platform default.

The setting is an absolute filesystem path. Saving it does not create the
directory. Required parent directories are created only when a clone starts.

When a repository name can be derived safely from the remote source, the initial
target is:

```text
<Default repositories folder>/<repository-name>
```

Repository-name derivation is best-effort and supports URI-style and SCP-style
Git remotes. It is not remote validation; Git owns final validation.

The local target begins as auto-generated. While it remains auto-generated,
changing the remote source updates the target. Explicit user editing or Browse
makes the target user-owned, and later source changes no longer overwrite it.

## Target safety

Before invoking Git:

- source text must be non-empty after trimming;
- target must be a valid absolute path;
- an existing file at the target is rejected;
- an existing non-empty directory is rejected;
- an existing empty directory is allowed;
- an absent target is allowed;
- absent parent directories may be created.

CSharpGit never deletes a partially created target automatically after failure or
cancellation.

## Draft and switch semantics

If leaving the current repository would discard an unapplied commit message,
confirmation is requested before clone starts. Accepting confirmation does not
immediately clear the draft.

```text
confirm discard
→ clone
→ open cloned local path through common switch
→ successful initial refresh
→ discard old draft
```

Clone failure or post-clone open failure leaves the previous workspace and draft
unchanged. If clone succeeded but opening failed, the cloned repository remains
on disk and the UI reports its local path.

## Progress, cancellation and concurrency

Clone is a potentially long-running user operation. The UI shows an indeterminate
busy state, disables editable clone inputs and prevents a second Clone.

Cancel propagates a cancellation token through the view model, clone service and
`GitCommandExecutor`; the existing executor owns process-tree termination.
Application shutdown cancels an active clone.

Clone, Create, Open/switch, Close and other workspace-changing operations do not
run concurrently. No artificial waiting delays are used.

## Entry points

The common Clone workflow is available from:

- the empty start screen;
- the Recent repositories launcher;
- the current-repository selector;
- the open-workspace application menu.

The start-screen overflow menu remains an application Settings/About menu.
No dedicated Clone keyboard shortcut is introduced.

## Failure semantics

Clone uses typed local/application failures for invalid target path, target file,
non-empty target, target creation failure, unavailable Git and local access
denial. Other Git failures preserve Git exit diagnostics without guessing remote
authorization semantics from stderr strings.

Cancellation remains `OperationCanceledException`, not a clone failure.

## Non-goals

This intent does not add branch/depth selection, shallow or partial clone,
sparse checkout, submodule options, mirror/bare clone, provider APIs, OAuth,
credential storage, custom terminal credential prompts, percentage progress,
progress parsing, retry, or destructive partial-clone cleanup.
