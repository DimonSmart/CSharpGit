# IDD-0004.spec-history-and-diff

## Intent

История commits, согласованный с ней graph, metadata выбранного commit и lazy Changes/diff дают пользователю центральное представление о развитии репозитория без предварительной загрузки всей истории и без Git work, которое не требуется видимой части UI.

## Behavior

- История показывает для commit как минимум graph, message, author, date/time, hash и refs.
- История отображает реальную topology: последовательности commits, branches и merges.
- Пользователь переключает scope как минимум между текущей branch и всеми доступными branches/refs; активный scope явно виден.
- История поддерживает filtering без требования расширенного query language.
- `HistoryRow.Commit` уже содержит full message, author, date/time, hash, parents и refs. При выборе history row эти metadata отображаются синхронно из уже загруженной history и не требуют Git CLI process.
- Нижняя details pane имеет `Commit` и `Changes`. Выбор commit сам по себе не означает запрос changed files или diff.
- Пока активен `Commit`, перемещение selection между уже загруженными history rows не запускает Git для commit details, changed files или diff и не показывает loading overlay.
- Changed files выбранного commit загружаются независимо и lazy только когда `Changes` активна. Сам факт создания/`Loaded` controls не делает Changes активной.
- Changed files представлены как иерархическое дерево repository-relative paths. File nodes показывают status и доступную added/removed statistics; folder nodes могут агрегировать statistics.
- После загрузки changed files допустимо выбрать первый file; diff загружается только для одного selected file и только пока `Changes` активна.
- Changed-files tree и selected-file diff используют одинаковую comparison base: первый parent обычного/merge commit; root commit сравнивается с empty tree/root semantics.
- Rename/copy сохраняют current path в `Path`, исходный path в `OriginalPath`; поддерживаются как минимум A/M/D/R/C и binary statistics.
- При смене selected file stale diff немедленно перестает отображаться, tree остается доступным, а loading overlay перекрывает только diff viewer.
- Compact unified diff различает added/removed/context/hunk rows, показывает old/new line numbers и скрывает служебный шум `diff/index/---/+++` из основного presentation.
- Binary file обозначается как binary вместо попытки текстового отображения.

## Durable Architecture And Constraints

- История загружается incrementally/lazily; graph строится из тех же history data.
- Commit graph layout принадлежит materialized history session: observed maximum lanes обновляется только по принятой новой batch, не уменьшается при scrolling/recycling, не требует дополнительного Git query или предварительной загрузки полной history. GRAPH расширяется от 120 до 200 px; после 200 px lane spacing сжимается от 16 до минимум 8 px, а более широкая topology безопасно clip-ится границей GRAPH.
- Commit graph geometry имеет structural identity по topology, effective row height и geometry-affecting metrics. Theme, graph width и line thickness являются presentation/layout state и сами по себе не перестраивают geometry. Virtualization/recycling переиспользует bounded history-session geometry cache; history reset очищает этот cache.
- Reflog-only state является presentation/reachability state: он может менять только render node и primitives persistent track текущего commit в пределах History row. Он не входит в `CommitTopology`, lane allocation, track identity или geometry/cache identity; изменение только этого state инвалидирует rendering без geometry rebuild.
- Commit selection является дешевой UI operation: metadata берется из `SelectedHistoryRow.Commit` и не зависит от `CommitDetails`/`ReadCommitAsync`.
- Changed files имеют отдельную lazy operation, возвращающую полный `ChangedFile` model (status, current/original paths, added/removed lines, binary) максимум одним Git CLI invocation на cache miss. Presentation не выполняет отдельный status query.
- Selected-file diff имеет отдельную lazy operation и максимум один Git CLI invocation на cache miss.
- Parent не определяется отдельной Git-командой в changed-files/diff hot path: он берется из `SelectedHistoryRow.Commit.Parents`.
- Interactive changed-files/diff path может использовать rename/copy detection, но не использует `--find-copies-harder`.
- Быстрая navigation при активной `Changes` debounce-ится примерно на 120 ms. Явное открытие `Changes` для уже выбранного commit может начать initial load сразу.
- Changed-files и diff operations имеют независимые `CancellationTokenSource` и generation/identity guards. Смена commit/file, уход с Changes и repository switch отменяют ненужную работу.
- Cancellation запущенного Git process завершает process tree и дожидается фактического exit/drain redirected streams; `OperationCanceledException` не показывается как пользовательская ошибка.
- Generation guards остаются обязательны даже при process cancellation: stale completion не может публиковать files/diff, менять selection/loading state или показывать error.
- Changed-files и просмотренные diffs имеют bounded session-level LRU caches. Cache key включает repository identity, commit, comparison parent/base; diff key дополнительно включает path. Cache hit не запускает Git.
- Repository switch отменяет current changed-files/diff work и очищает session caches.
- Async changed-files/diff loading не переводит приложение в global Busy и не блокирует history navigation.
- `Loading changes…` относится только к Changes/file-tree surface; `Loading diff…` — только к diff area. `Loading commit…` отсутствует в обычной history navigation.
- Selection-driven UI preparation (например состояние кнопок historical file actions) не должна скрыто запускать Git. Дополнительный Git разрешен только после явного пользовательского file action.
- Debug diagnostics фиксируют duration/cache hit|miss для changed-files/diff и Git operation duration, не логируя полный diff output.
- Background prefetch changed files/diffs не входит в текущую реализацию: `not visible = not loaded`.

## Performance Budget

- `Commit` active + select already-loaded commit: **0 Git processes**.
- `Changes` active + changed-files cache miss after debounce: **<= 1 Git process**.
- Select file + diff cache miss: **<= 1 additional Git process**.
- Changed-files/diff cache hit: **0 Git processes**.
- Нет дополнительных processes для metadata, parent lookup, status lookup или first-parent resolution.

## Large Diff Preview Guard

- Historical changed-file statistics already loaded by `ReadChangedFilesAsync` are reused as the zero-cost preflight signal. A non-binary file with at least 10,000 added+removed lines is selected normally, but its diff is not started automatically; the diff surface explains the cost and offers an explicit `Load diff` action.
- Automatic selected-file diff generation has a 1 MiB stdout safety limit. The limit is enforced while Git stdout is streamed, before the full patch is materialized as a `string`, parsed into `FileDiff`, cached, or projected into UI rows.
- Crossing the automatic output limit terminates the current Git process and produces a dedicated large-diff state, not a generic load error and not a partial diff.
- `Load full diff anyway` starts a fresh generation-safe request with the stdout limit disabled. Partial output from the aborted preview is never reused.
- The guard does not add a size/status Git probe to the normal history hot path. Cache hits and normal previews retain the existing process budget.

## Non-Goals

- Изменение алгоритма commit graph topology, history ordering/incremental loading или branch/ref navigation.
- Working-tree diff/staging/commit/rebase/merge workflows.
- Background prefetch в первой реализации.
- `--find-copies-harder` в interactive navigation path.
- Persistent disk cache changed files/diffs.
- Специализированные viewers для binary formats или обязательный side-by-side diff.

## Acceptance Criteria

- Metadata выбранного commit появляется сразу из `HistoryRow.Commit`; `ReadCommitAsync` не участвует в обычной history navigation.
- На `Commit` любое перемещение между уже загруженными rows создает 0 Git CLI processes.
- Changed files не загружаются, пока `Changes` не активна.
- Changed-file model на cache miss получается максимум одним Git process и presentation не запускает отдельный `ReadFileStatusesAsync`.
- Diff одного selected file требует максимум одного дополнительного Git process.
- Fast ↑/↓ navigation не создает очередь Git processes; после остановки публикуется только актуальный commit.
- Obsolete operations реально cancel/terminate subprocess и дополнительно защищены generation checks.
- First-parent semantics согласованы между changed-files и diff; root commit работает без parent lookup.
- Rename/copy current/original paths, status/statistics и binary state корректны; `--find-copies-harder` отсутствует в hot path.
- Возврат к недавно просмотренному commit/file использует bounded cache и 0 Git processes.
- Stale files/diff никогда не показываются как данные нового commit/file.
- `Loading commit…` отсутствует; local Changes/Diff loading overlays не включают global Busy.
- IDD intent и implementation не противоречат друг другу.

## Reusable compact diff presentation

The compact unified-diff presentation (OLD/NEW line numbers, hunks, context/add/remove highlighting, binary state, and standard Git-header suppression) is reusable product UI. Commit Changes and the selected-file Working Tree diff use the same `FileDiff -> DiffLine -> CompactDiffLine` semantics and the same compact item template/resources.

## Selectable Commit Information And Diff Text

- Commit Details read-only values that users reasonably copy — full message, author, displayed date/time, full commit hash, parent hashes and the root-parent placeholder — support normal desktop text selection in addition to the existing exact-value Copy actions.
- Historical compact diff exposes the displayed `CompactDiffLine.Text` values as one continuous logical text surface joined with `Environment.NewLine`, with no synthetic trailing newline and without OLD/NEW gutter numbers.
- Text selection may begin and end at arbitrary character positions across multiple displayed diff lines. Unified-diff prefixes and displayed hunk/header text are ordinary selectable text.
- `Ctrl/Cmd+C` copies only the selected character range and `Ctrl/Cmd+A` selects the entire displayed logical diff text.
- Diff selection is presentation-only, is cleared when the semantic diff source changes, survives ordinary scrolling of the same source, and does not start Git work.
- Historical and Working Tree compact diff reuse the same selectable diff presentation implementation while preserving line-number gutters, diff-kind backgrounds, no-wrap monospace text, scrolling and binary-file behavior.

## Semantic Diff Viewport And Explicit Surface States

- Viewport belongs to a semantic diff, not to its rendered text. Every semantic replacement through the shared `SelectableDiffViewer` clears native text selection and starts at horizontal/vertical offset `(0,0)`, even when two sources render identical logical text.
- Ordinary scrolling of the already displayed semantic diff is preserved. A layout-aware deferred reset is generation-safe and is cancelled by newer content or by user interaction, so an old callback cannot scroll a newer diff.
- `Clear()` is also a semantic replacement: it clears content/selection/diagnostics, resets offsets and invalidates an older deferred reset.
- Commit Changes has explicit stable states rather than an unexplained blank surface: nothing selected, local diff loading, text, image loading/image, other binary, no textual patch, unavailable and error.
- A non-binary historical `FileDiff` that still belongs to the selected immutable commit but produces no compact textual rows is presented as `No textual diff`, not as an empty viewer.
- Diff-load errors have a local final `Could not load diff` presentation in addition to the existing application error reporting. Stale requests cannot publish it.
- Refresh that restores the same commit by hash also restores the previously selected changed-file path when it still belongs to that commit. Current/original rename paths are treated as the same semantic file for restoration. The restored diff is a semantic reload and begins at `(0,0)`.
- `FileDiff.Diagnostics` carries typed invisible-change metadata separately from `DiffLine.Text` and `CompactDiffLine.Text`. The parser preserves whether a raw diff line ended in CRLF while keeping display/copy text free of the transport `\r`.
- Conservative diagnostics include UTF-8 BOM added/removed and unambiguous LF ↔ CRLF changes. Git's existing `\ No newline at end of file` row remains part of the visible logical diff; typed metadata does not duplicate it in the UI.
- Diagnostics are derived from the already loaded diff on the ordinary path and do not add a mandatory Git subprocess. Diagnostic badges/info do not become part of copied logical diff text.
- Text/image/other-binary classification and no-textual-patch classification are shared presentation logic with Working Tree; image semantics remain owned by IDD-0038.

## Semantic reference decorations and topology boundary

History row reference decorations are semantic annotations, not graph topology. Presentation receives typed reference metadata for current local branch, other local branches, remote-tracking refs, tags and detached HEAD; XAML/presenter code must not infer those types from display-name prefixes.

Current local branch may additionally carry its configured upstream and the already-loaded ahead/behind counters. These annotations never add lanes or edges. Remote-tracking refs stay attached only to the commit they actually reference.

Reflog ghost metadata is also an annotation. It never creates dotted lanes, pseudo-branches or links between old and new ref positions. A real parent-relationship divergence remains a real graph fork and must not be visually flattened merely because one tip is local and another is remote-tracking.

For a reflog-only History row the node and graph primitives whose `TrackId` equals `CommitGraphRowVisual.NodeTrackId` are rendered with a muted neutral style. Independent tracks that only pass through the same row retain their normal palette. This styling is row-local and never creates a separate “reflog graph”, lane or edge.
