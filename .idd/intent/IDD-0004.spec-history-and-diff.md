# IDD-0004.spec-history-and-diff

## Intent

История commits, согласованный с ней graph, подробности выбранного commit и
встроенный diff дают пользователю центральное представление о развитии
репозитория без предварительной загрузки всей истории.

## Behavior

- История показывает для commit как минимум graph, message, author, date/time,
  hash и относящиеся к нему refs.
- История отображает реальную topology: последовательности commits, branches и
  merges.
- Пользователь переключает scope как минимум между текущей branch и всеми
  доступными branches/refs; активный scope всегда явно виден.
- По умолчанию предпочтителен scope всех доступных refs, если он не создает
  существенных проблем производительности или usability.
- История имеет основные колонки; их набор или отображение допускает настройку,
  а продуктовая логика не зависит от фиксированного table layout.
- История поддерживает поиск или фильтрацию по основным пользовательским
  критериям без требования расширенного query language.
- Commit graph показывает последовательность, создание branches, merges и
  несколько одновременно существующих branches. Его строки остаются согласованы
  со строками истории.
- При выборе commit видны full message, author, date/time, hash, parents, refs и
  измененные файлы.
- Измененные файлы выбранного commit представлены как иерархическое дерево по
  repository-relative path, а не только как плоский список. Цепочки каталогов с
  единственным дочерним каталогом могут визуально схлопываться в compact path.
- Для file nodes видны Git status и доступная статистика added/removed lines; для
  folder nodes допускается агрегированная статистика дочерних файлов.
- Выбор file node показывает его изменение рядом с деревом в том же changes
  surface без обязательного перехода на отдельную вкладку diff.
- Когда выбранный файл уже однозначно отображается в соседнем changed-files tree,
  compact diff viewer не расходует отдельную вертикальную строку на повторное
  отображение имени или пути этого файла. Доступное пространство преимущественно
  используется для содержимого diff.
- Разделитель между деревом файлов и diff viewer изменяет ширину обеих частей.
- Встроенный viewer показывает textual changes как compact unified diff,
  визуально различает added, removed, context и hunk/header rows и показывает
  old/new line numbers там, где они существуют.
- Низкоуровневые служебные file headers unified diff (`diff --git`, `index`,
  `---`, `+++`) не занимают постоянное место в основном compact presentation;
  границы hunks (`@@ ... @@`) сохраняются.
- Для binary file вместо попытки текстового отображения показывается понятное
  обозначение binary data.

## Durable Architecture And Constraints

- История загружается incrementally/lazily и начинает отображаться до загрузки
  полного набора commits большого репозитория.
- Graph не имеет независимой authoritative topology model и строится из тех же
  Git-данных, что и история.
- Custom drawing допустим для graph, если стандартные controls недостаточны.
- Данные, не нужные текущему отображаемому состоянию, не загружаются заранее.
- Дерево changed files является presentation projection уже загруженного списка
  файлов commit и не требует отдельного обхода working directory.
- Compact diff presentation является projection выбранного unified diff; смена
  выбранного файла сохраняет lazy loading и не должна загружать diffs остальных
  файлов commit заранее.
- Presentation compact diff не меняет Git semantics и не удаляет информацию из
  source diff model, необходимую другим будущим viewers.

## Non-Goals

- Расширенный язык запросов истории в первой версии.
- Специализированные viewers для изображений, архивов и иных binary formats.
- Обязательная поддержка внешнего diff tool в MVP.
- Жестко фиксированный layout колонок.
- Обязательный side-by-side diff mode в рамках compact unified viewer.

## Acceptance Criteria

- Пользователь видит историю и topology, переключает ее scope и однозначно
  понимает текущий выбор.
- Выбор commit открывает полные metadata и дерево измененных файлов.
- Общие path prefixes представлены каталогами; single-child folder chains могут
  быть compacted без потери полного пути файла.
- Выбор textual change немедленно показывает unified diff рядом с деревом файлов.
- Когда changed-files tree уже однозначно показывает выбранный файл, commit
  compact diff не дублирует его имя или путь отдельной строкой над diff content.
- Diff показывает old/new line numbers, различимые added/removed/context rows и
  hunk boundaries, не засоряя основную область стандартными `diff/index/---/+++`
  file headers.
- Пользователь может менять ширину file tree и diff viewer splitter-ом.
- Binary change не интерпретируется как текст.
- Большой репозиторий не требует полной загрузки истории или diffs всех файлов
  перед первым полезным отображением.

## Verification

- Проверяются linear, branched и merged histories, включая несколько refs на
  commit и несколько активных ветвей graph.
- Проверяются оба scope, filtering и согласованность graph со строками history.
- Проверяется построение changed-file tree для общих prefixes, вложенных folders,
  root files и compact single-child folder chains.
- Проверяется compact diff projection: line numbers для context/added/removed,
  hunk boundaries и исключение стандартных noise headers.
- Проверяется, что commit Changes compact diff не резервирует отдельную строку
  под имя/путь файла, если выбор уже виден в соседнем changed-files tree.
- Проверяются textual и binary changes, commits с несколькими parents и большие
  истории с incremental loading.
- В запущенном UI проверяются scrolling, resizing, tree selection, согласованность
  выбранного файла с diff, выравнивание graph/history и отображение реальных
  данных.

## Reusable compact diff presentation

The compact unified-diff presentation (OLD/NEW line numbers, hunks, context/add/remove highlighting, binary state, and standard Git-header suppression) is reusable product UI. Commit Changes and the selected-file Working Tree diff use the same `FileDiff -> DiffLine -> CompactDiffLine` semantics and the same compact item template/resources.
