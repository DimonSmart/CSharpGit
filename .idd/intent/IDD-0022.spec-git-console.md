# IDD-0022.spec-git-console

## Intent

CSharpGit предоставляет встроенную session-level Git Console, чтобы пользователь
мог видеть реальные Git CLI commands, запускаемые приложением, их arguments,
working directory, stdout, stderr, exit code и duration без превращения основного
workspace в постоянно открытый terminal.

## Behavior

- Git Console располагается в нижней части repository workspace непосредственно
  над status bar и по умолчанию скрыта.
- Status bar показывает последнюю релевантную Git command и является основной
  ручной точкой входа в console. В обычном режиме приоритет имеет последняя User
  command; в режиме All commands допустима последняя command любого вида.
- Console показывает session history newest-first и имеет фильтр `User commands` /
  `All commands`; default — `User commands`.
- История содержит максимум 100 последних Git CLI invocations по всей session.
  Лимит фиксированный и не является пользовательской настройкой. При добавлении
  101-й записи удаляется самая старая.
- Каждая command появляется в истории сразу после успешного запуска process со
  status `Running`, а после завершения обновляется до `Succeeded`, `Failed` или
  `Cancelled` вместе с exit code, stdout, stderr и duration.
- User/Internal — семантическая классификация назначения invocation, а не только
  Git subcommand. Команды прямого пользовательского действия являются User;
  команды чтения состояния и данных UI являются Internal.
- Console details показывают command, working directory, started time, duration,
  exit code, stdout и stderr. Вывод моноширинный, selectable и copyable.
- `Copy command` копирует человекочитаемую shell-like Git command. `Copy all`
  копирует диагностический текст с command metadata и обоими output streams.
- Console не является interactive terminal: ввод произвольных commands и Run again
  отсутствуют.
- Manual open выбирает последнюю User command, иначе последнюю Git command; при
  пустой истории показывается нейтральное empty state.
- Shortcut toggles console: предпочтительно `Ctrl+`` и `Cmd+`` на macOS, если
  framework/platform не требует ближайшей совместимой комбинации.

## Auto Open

- В Settings / Diagnostics находится `Git Console / Auto open` со значениями
  `On errors`, `Always`, `Never`; default — `On errors`.
- `On errors` автоматически открывает console и выбирает failed User command.
- `Always` открывает console при старте User command.
- `Never` никогда не открывает console автоматически.
- Internal commands сами по себе не раскрывают panel.

## Durable Architecture And Constraints

- Git execution layer не зависит от Presentation. Git invocations публикуют
  activity через application-level abstraction; Presentation подписывается на
  observable session history.
- Сбор activity централизован в общем Git process execution path. Сервисы, которым
  требуется captured result или streamed-to-file output, используют тот же runner
  и тот же activity sink вместо отдельного UI-specific logging.
- Existing application-level Git error messages сохраняются. Git Console является
  дополнительным diagnostic source и не заменяет понятные ошибки пользователя.
- Existing OperationBanner для merge/rebase/conflicts сохраняет независимую роль:
  он управляет active Git operation, а Console только показывает invocations/output.
- Environment variables Git process не отображаются и не сохраняются в Console.
- Sensitive command-line data (credentials, tokens, passwords, authorization data)
  маскируются до попадания в history/display/copy surfaces.
- Для одной command сохраняется не более 1 MiB stdout и 1 MiB stderr; превышение
  явно маркируется `[output truncated]`.
- History существует только в памяти процесса и очищается при завершении CSharpGit.

## Non-Goals

- Интерактивный terminal или shell prompt.
- Произвольный ввод Git commands.
- Повторный запуск сохранённой command.
- Persistence history между sessions.
- Настраиваемый или неограниченный history limit.
- Замена OperationBanner или существующей application error handling.

## Acceptance Criteria

- Все Git CLI process paths регистрируют Started и final state через общий activity
  mechanism; независимых обходных process paths для обычных Git invocations нет.
- History никогда не превышает 100 entries и поддерживает User/All filtering.
- Entry содержит started/completed timestamps, duration, directory, executable,
  arguments/display command, kind, status, exit code, stdout и stderr.
- Failed и cancelled commands сохраняют diagnostic data и корректный status.
- Command formatting корректно quotes arguments с spaces и пригодно для copy.
- Secrets в поддерживаемых URL/options/authorization forms маскируются.
- stdout/stderr truncation ограничивает memory и явно виден пользователю.
- Status bar, manual open/close, auto-open modes, copy actions и empty state работают
  независимо от OperationBanner.
- Existing tests продолжают проходить; новые tests покрывают history limit,
  success/failure/cancel, filtering, formatting, truncation, sensitive data,
  settings persistence и UI contracts.
