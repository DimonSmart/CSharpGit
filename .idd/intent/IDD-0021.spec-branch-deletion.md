# IDD-0021.spec-branch-deletion

## Intent

Пользователь безопасно удаляет local и remote branches из Repository Tree с явным
подтверждением, стандартной Git semantics и предсказуемым поведением при частичном
успехе. Local deletion остаётся safe-by-default, но пользователь может явно выбрать
force deletion для конкретной операции в local confirmation dialog.

## Behavior

- `Delete` для local branch всегда открывает confirmation dialog. Current local
  branch и branch, используемую существующим worktree, удалить через этот action
  нельзя; существующие busy/mutation restrictions сохраняются.
- Local confirmation содержит выключенный по умолчанию checkbox
  `Force delete even if the branch is not fully merged`. Checkbox создаётся заново
  для каждой операции и не сохраняется в ViewModel, settings или session state.
- Под Force option отображается предупреждение, что force deletion может удалить
  единственную branch reference на commits и усложнить их восстановление; UI не
  утверждает, что commits немедленно физически удаляются из repository.
- Без Force local branch удаляется стандартным `git branch --delete`.
- После явного включения Force local branch удаляется через
  `git branch --delete --force`.
- Git остаётся source of truth для merge safety. Приложение не вычисляет
  merged/unmerged state или reachability commits, не парсит Git error для выбора
  режима и не повторяет неудачный safe delete автоматически как force delete.
- Force option не делает current/worktree-owned branch доступной для `Delete`, не
  выполняет checkout/detach HEAD и не изменяет или удаляет worktrees.
- `Delete` для remote branch всегда открывает confirmation dialog и удаляет branch
  на remote repository через `git push <remote> --delete <branch>`. Remote deletion
  workflow не получает Force option.
- Если найдена соответствующая local branch, confirmation remote deletion содержит
  выключенный по умолчанию checkbox для её дополнительного удаления.
- Corresponding local branch сначала определяется по `Upstream`, равному полному
  имени выбранной remote branch. При отсутствии tracking branch применяется
  fallback по имени branch без configured remote prefix.
- Remote определяется по списку configured remotes; имя branch не разбирается
  простым разделением по первому `/`. При совпадении нескольких prefixes выбирается
  наиболее длинный configured remote prefix.
- Если соответствующая local branch является current, remote branch по-прежнему
  можно удалить, но checkbox local deletion disabled и UI объясняет причину.
- При комбинированном удалении remote branch удаляется первой. Local branch
  удаляется только после успешного remote deletion и всегда в safe mode через
  `git branch --delete`; force state local dialog в этот workflow не переносится.
- Если remote deletion успешен, а safe local deletion отклонён Git, remote deletion
  не откатывается. Пользователь получает явное сообщение о partial success вместе с
  Git error.
- Ошибка remote deletion не запускает local deletion.
- После успешного или частично успешного удаления repository state обновляется
  существующим mutation/refresh механизмом. Если history был scoped к фактически
  удалённой branch, UI возвращается к `All references`.

## Durable Architecture And Constraints

- Branch deletion использует `IReferenceService` и существующий
  `GitCliRepositoryService`; safe/force intent представлен strongly typed mode, а
  отдельный Git execution layer или отдельный force-delete service не создаётся.
- Safe и force deletion используют существующий mutation execution mechanism.
- Remote deletion использует существующую Git push/authentication infrastructure,
  credential helpers, SSH configuration и обработку Git errors.
- Операции выполняются асинхронно и участвуют в существующем busy/mutation
  механизме, который блокирует конфликтующие mutations и refresh-ит repository.
- Приложение не переключает branch автоматически ради удаления.

## Non-Goals

- Force deletion local branch как часть combined remote/local deletion.
- Массовое удаление branches.
- Изменение semantics удаления remote branches.
- Автоматическое определение merged/unmerged status.
- Анализ или preview commits, которые могут потерять branch reference.
- Undo или восстановление deleted branch по SHA/reflog.
- Автоматический checkout другой branch.
- Автоматическое изменение или удаление worktree ради удаления branch.
- Автоматический retry safe deletion как force deletion.
- Удаление tags или remotes.
- Собственная authentication система.
- Новый Git execution mechanism.

## Acceptance Criteria

- Local delete confirmation содержит Force checkbox и предупреждение; checkbox
  выключен при каждом новом открытии dialog.
- Без Force local deletion использует `git branch --delete`; force deletion
  происходит только после явного opt-in и использует `git branch --delete --force`.
- Force не делает current или worktree-owned branch доступной для `Delete` и не
  ослабляет existing busy/mutation restrictions.
- Приложение не пытается самостоятельно определять merged status или потенциально
  unreachable commits; Git refusal сохраняет branch и проходит через existing error
  handling.
- Remote branch имеет confirmed `Delete` action без Force option и действительно
  удаляется на remote repository через Git push delete.
- Remote confirmation предлагает соответствующую local branch только когда она
  найдена; checkbox выключен по умолчанию и disabled для current branch.
- Tracking relationship имеет приоритет над name fallback, configured remote prefix
  корректно сохраняет branch names с несколькими `/`.
- Combined remote/local deletion удаляет remote первой, local всегда удаляет safe и
  сохраняет existing partial-success semantics.
- После операции Repository Tree, refs, badges и history scope не содержат stale
  reference на удалённую branch.

## Verification

- Git integration tests используют реальный local repository и bare remote и
  проверяют merged Safe deletion, refusal + сохранение unmerged branch в Safe/default
  mode, успешное Force deletion unmerged branch, remote deletion и branch names с `/`.
- Application tests покрывают upstream-first resolution, name fallback, configured
  remote prefixes, отсутствие local branch и current local branch.
- Desktop contract tests проверяют local Force checkbox и warning, Safe/Force mode
  selection, сохранение local eligibility restrictions, отсутствие Force в remote
  dialog, explicit Safe в combined workflow, порядок remote-then-local и
  partial-success UI.
