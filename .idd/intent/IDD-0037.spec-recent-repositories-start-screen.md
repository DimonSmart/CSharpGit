# IDD-0037.spec-recent-repositories-start-screen

## Intent

Стартовый экран CSharpGit должен оставаться удобным при большой истории локальных
репозиториев: recent repositories можно быстро найти, важные репозитории можно
закрепить и расположить вручную, а empty state и список recent repositories не
перекрывают друг друга.

## Behavior

- При отсутствии открытого repository start screen имеет явные состояния:
  обычный empty state при пустой history и repository launcher при непустой.
- Repository launcher exposes repository lifecycle actions in the order
  `Open repository`, `Clone repository`, `Create repository`, `Remove missing`.
  Clone delegates to IDD-0040 and does not duplicate cloning semantics here.
- Repository launcher избегает повторяющихся заголовков: page title —
  `Repositories`, группы называются `Favorites` и `Recent`, а search field
  использует короткий placeholder `Search by name or path…`. Отдельный
  поясняющий subtitle над search не показывается.
- Смысл start-screen элементов не определяется их индексом в
  `RootLayout.Children`; empty state, recent host и application menu имеют
  явные XAML hosts/names.
- Хранится до 1000 незакреплённых recent repositories и любое количество
  закреплённых.
- Закреплённые репозитории отображаются по пользовательским группам в порядке `Order`; `Recent` остаётся отдельной системной секцией.
- Новый pin добавляется в конец pinned group. Повторное открытие repository
  обновляет recent metadata, но не меняет пользовательский pinned order.
- Unpin возвращает repository в обычную recent history по `LastOpenedUtc`; при
  переполнении удаляется самый старый unpinned repository.
- Пользователь может менять pinned order drag-and-drop и командами
  `Move earlier` / `Move later`. При активном search reorder отключён.
- Search фильтрует уже загруженные элементы немедленно и case-insensitive по
  display name, path и last branch. Search не выполняет Git, filesystem,
  network или image-cache operations.
- Если search не дал результатов, search field остаётся доступным и показывается
  отдельное состояние `No repositories match your search.`.
- Enter в поле поиска при непустом запросе открывает репозиторий через существующее действие карточки, только если во всех отфильтрованных pinned-группах и секции Recent ровно одна карточка. При нуле или нескольких совпадениях Enter ничего не открывает. Пустой или пробельный запрос не вызывает автоматического открытия.
- `Remove from recent` удаляет pinned и unpinned repository одинаково.
  `Remove missing` повторно проверяет filesystem перед удалением кандидата.
- Отсутствующий repository остаётся в своём пользовательском pinned order и
  визуально помечается `Folder not found`.
- Launcher растягивается по доступной клиентской ширине без искусственного
  центрального `MaxWidth`. Все группы и секция Recent используют одинаковый
  `RepositoryTileGridView` + `VariableSizedWrapGrid` с базовыми адаптивными
  ячейками (Compact обычно 260–340 DIP), gutter 8 DIP и одинаковой высотой
  карточек около 112 DIP при нормальном text scale.
- Готовый `Preview` занимает две базовые колонки при 2+ колонках сетки;
  `Icon` и glyph остаются одноколоночными. При одной колонке Preview имеет
  компактный адаптивный media slot.
- В Wide-карточке изображение находится слева во всю высоту видимой карточки,
  без отдельной рамки, цветной подложки и внутренних отступов; скругление
  относится к внешнему краю всей карточки. Ширина Preview определяется
  декодированным aspect ratio и ограничениями под текст/команды: обычно около
  213 DIP для 1200×630 при высоте 112 DIP, не более 360 DIP, не менее
  236 DIP справа для текстовой зоны с внутренними отступами.
- Число базовых колонок определяется только фактической шириной `GridView`:
  `floor(width / 268)` с минимумом 1 для положительной ширины;
  при `width=535.99` одна колонка, при `width=536` две по 268 DIP.
  Одна Compact-карточка не растягивается сверх 340 DIP видимой ширины.
  Wide занимает `2 * CellWidth - 8` DIP, Compact — `CellWidth - 8` DIP.
  Незанятое место в конце строки допустимо; reorder/backfill, нарушающий
  коллекционный row-major порядок, запрещён. Нет horizontal scroll; resize
  не выполняет I/O и не пересоздаёт коллекции.
- Все repository tiles используют единую информационную иерархию: display
  name, отдельную строку path и отдельную metadata-область с branch +
  last opened. При Wide Preview пропорциональное изображение находится слева,
  текст и action buttons — справа, Pin/Remove вверху справа. Видимый image
  kind и span определяются только presentation и правилами IDD-0016.
- Pin и Remove/X расположены рядом как компактная action group в правом верхнем
  углу текстовой области плитки, но без общей фоновой capsule/рамки. Они не
  перекрывают path, metadata или preview.
- Обе action buttons используют общий `RepositoryTileActionButtonStyle`;
  Pin остаётся заметным в pinned и unpinned state, а каждая кнопка сохраняет
  собственные hover, pressed и keyboard-focus states.
- Длинная branch metadata может занимать до двух строк с trimming после
  приоритетного показа начала branch; path при этом остаётся самостоятельной
  строкой и не конкурирует с branch за одну строку.

- Пользователь может создавать, переименовывать, упорядочивать, сворачивать и удалять виртуальные группы закреплённых репозиториев. Группа с ID `favorites` существует всегда; её можно переименовать и переставить, но нельзя удалить. Пустые группы сохраняются.
- Репозиторий принадлежит не более одной группе. Pin при единственной группе выполняется сразу, при нескольких группах требует выбора; Move to group не меняет recency или изображения. Delete group переносит pins в конец Favorites.
- Search по содержимому карточек показывает только группы с результатами, временно раскрывает их и не сохраняет это раскрытие. Reorder при поиске запрещён, перенос между группами разрешён.
- DnD reorder разрешён только внутри одной раскрытой группы; межгрупповой drop запрещён.
- Launcher видим при непустой history либо при наличии пользовательских групп, даже если они пусты. На первом запуске без истории остаётся прежний empty state.

## Durable Architecture And Constraints

- Persisted recent model содержит `IsPinned`, nullable `PinnedOrder`, nullable `GroupId` и отдельный список RepositoryGroups в том же settings.json. Индексы pinned локальны группе;
  legacy JSON без этих свойств остаётся совместимым.
- `JsonAppSettingsService` централизованно нормализует path deduplication,
  pinned order и лимит unpinned history. После mutation committed state остаётся
  нормализованным.
- Pinned order и `LastOpenedUtc` независимы.
- Presentation строит grouped projection persisted state на groups/recent + search, но
  не редактирует JSON напрямую.
- Existing `RecentRepositoryItem` переиспользуется при pin/unpin/reorder и
  metadata updates. Простое изменение settings не должно повторно выполнять
  `Directory.Exists` для всех элементов или инвалидировать repository-image
  cache.
- Availability является snapshot item state; явный `Remove missing` имеет
  право повторно проверить filesystem.
- Action buttons launcher занимают собственную верхнюю колонку карточки, не
  перекрывают title, path и metadata; на очень узких окнах текст сокращается.
- Repository tile action buttons имеют shared semantic application-level
  style без общей декоративной capsule. Открывающая карточку кнопка и
  Pin/Remove — sibling controls, а не вложенные интерактивные элементы.
- Grid metrics принадлежат presentation, не ViewModel или settings. Resize
  обновляет только базовую ширину ячеек, готовые preview spans и media geometry;
  не пересоздаёт items, не выполняет Git/FS и не разрешает изображения.
  Размеры учитывают item margins/gutters. При неверном/неизмеренном viewport
  безопасный span 1. Для Wide внутренние отступы переносятся с корня на
  текстовую область; Compact-карточки не теряют прежнее оформление.
- Span устанавливается на `GridViewItem` через `VariableSizedWrapGrid.SetColumnSpan`.
  Prepare/clear/recycle/unload создают и снимают подписки только своего
  container/item; поздние property notifications не воздействуют на новый
  контейнер. События bitmap decode не должны зависеть от Collapsed images.
- В одной строке сохраняется исходный порядок элементов коллекции. Перенос
  двухколоночной карточки в новую строку может оставлять незанятую ячейку.
  DnD target определяется по настоящему `GridViewItem`, reorder только в
  одной группе и только при выключенном поиске.

## Acceptance Criteria

- Empty state больше не перекрывает Recent repositories.
- До 1000 unpinned repositories сохраняются независимо от pinned repositories.
- Pin/unpin и manual pinned order переживают restart.
- Search по name/path/branch обновляет обе секции без I/O и сохраняет их порядок.
- Drag-and-drop reorder и `Move earlier` / `Move later` используют один
  persisted order и отключены при search.
- `Icon` и glyph используют Compact со span 1, готовый Preview — Wide
  со span 2 при 2+ колонках и Compact Preview со span 1 при одной.
  Wide Preview примыкает к левому, верхнему и нижнему краям карточки без
  вложенной рамки, сохраняя пропорции и свободное место под текстовые действия
  справа; кэш и приоритеты не изменены. Отказ декодирования не оставляет
  пустого wide container.
- Pin одинаково заметен на всех карточках; Pin + Remove/X визуально
  расположены рядом, но не заключены в общий capsule/container.
- Path отображается отдельной строкой; branch + last opened не конкурируют с
  path и могут аккуратно занять вторую metadata-строку при длинной branch.
- Action buttons не перекрывают display name, path, metadata или preview и
  имеют заметные индивидуальные hover/pressed/focus states.
- Remove actions работают для pinned repositories, а pinned order после удаления
  остаётся плотным и детерминированным.
- Узкий start screen не содержит overlap controls и горизонтального scroll;
  широкое окно использует всю доступную ширину с ограничением ширины карточки.
- При нормальном масштабе сетка дает ориентировочно 2/3/4/5/7 колонок на окнах
  700/1024/1280/1536/1920 DIP, с учетом фактического viewport и scrollbar.
- При увеличенном text scale текст и кнопки не обрезаются; при необходимости
  увеличивается единая высота ячейки всех элементов.
- Repository launcher не дублирует `Recent repositories` в page title и section
  heading и не добавляет избыточный explanatory subtitle над search.
- Clone action находится рядом с Open/Create и ведёт в общий clone workflow из IDD-0040.

## Verification

- Unit tests покрывают лимит 1000 unpinned, pin/unpin persistence, manual order,
  legacy JSON, invalid order normalization, duplicate paths и persistence
  failure.
- Projection tests покрывают search по name/path/branch, case-insensitive
  matching и независимую сортировку pinned/recent.
- Start-screen contract tests проверяют explicit hosts, отсутствие positional
  `RootLayout.Children` assumptions, search/pin/reorder controls, dynamic span
  на GridViewItem, prepare/clear/unload и защиту от stale bitmap callbacks.
  Отдельно проверяются flush-left media без wide backdrop, расположение кнопок
  справа, реакция на новый aspect ratio и снятие подписок tile при unload.
  Table-driven unit tests проверяют число колонок, 535.99/536 thresholds,
  Compact/Wide gutter, narrow fallback, resize 1→2→1→3, width по aspect
  ratio и отсутствие overflow.
- Вручную проверяются normal/pinned Icon/Preview/glyph tiles с короткими и
  длинными path/branch, включая hover, pressed и keyboard focus обеих кнопок.
- Проверяется, что action group без общей capsule не конфликтует с media slot и
  заголовком, а metadata wrapping/trimming не увеличивает visual overload.
- Runtime после Arrange измеряются ActualWidth и gutters на границах 2/3,
  3/4, 4/5 и 5/6 колонок, в том числе при появлении scrollbar. Дымовые
  тесты с 100 и 1000 элементами подтверждают scrolling, DnD между строками,
  async image update и отсутствие layout oscillation при resize. Windows и
  macOS проверяются при 100/125/150% scaling.
- CI build и существующий test suite проходят.
