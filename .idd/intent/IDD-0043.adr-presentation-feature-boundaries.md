# IDD-0043.adr-presentation-feature-boundaries

## Status

Accepted

## Context

The main desktop page had become a collection of partial files whose implementation
could read or mutate state owned by unrelated features. Repository garbage collection
combined service calls, mutation lifetime and a ContentDialog inside MainPage.
File-version operations re-read mutable selection when callbacks from asynchronously
prepared context menus were invoked.

Architecture Stabilization stage 1 introduced repository-session read lifetimes and
a single shared mutation gate. Feature extraction must reuse those mechanisms and
preserve product behaviour in IDD-0017, IDD-0023, IDD-0024, IDD-0032 and IDD-0039.

## Decision

MainPage owns XAML composition, event routing, dialog presentation and the page's
UI lifetime. Business/application workflows belong to independent feature ViewModels:

- RepositoryMaintenanceViewModel owns GC preparation, options, execution state and
  typed outcomes. RepositoryMaintenanceDialog owns only the UI and invokes semantic
  operations with a captured repository. The close guard projects the ViewModel's
  IsRunning state.
- FileActionsViewModel owns the authoritative OLD/NEW pair, snapshot-path resolution,
  external diff launching, reveal validation and independently versioned Commit and
  Working Tree selection slots. Event adapters capture immutable commit/working-tree
  requests before awaiting. Context menus bind their callbacks to the originating
  request and prepared pair, never to a later selection.
- Stage, Unstage and Discard remain WorkingTreeViewModel operations; menu callbacks
  reject stale selections before executing their existing commands.
- OpenRepositoryViewModel remains the sole owner of the repository session and
  mutation gate. Its narrow maintenance and file-action contexts provide the
  expected-repository validation and cancellable reads without introducing another
  lock or cancellation infrastructure.
- GC takes the existing gate non-blockingly, rechecks repository identity, shutdown,
  switch-in-progress, busy and current Git operation after the successful acquisition,
  then refreshes locally and releases the gate before IsRunning is reset. The
  current workspace's WorktreesViewModel is supplied as a targeted asynchronous
  callback by the page composition, not resolved a second time from transient DI.
- The Git tool configuration boundary now reports missing configuration with
  GitToolNotConfiguredException, derived from InvalidOperationException. Other
  configured-tool errors preserve their established messages and behaviour.

Each extracted workflow has one owner and Dispose invalidates delayed operations.
Results are marshalled to the existing UI dispatcher for bindable notifications.
Historical snapshot preview remains a separate Repository Files scenario.

## Alternatives Considered

Continue expanding MainPage partial files: rejected because all partials still share
private state and can violate the session/selection invariants.

Move feature-specific logic to OpenRepositoryViewModel: rejected because it would
grow the composition root into another application workflow owner.

Create another GC semaphore or a new global service locator: rejected because either
would bypass existing serialization and ownership rules.

Resolve WorktreesViewModel from DI inside maintenance: rejected because transient
resolution would refresh an unrelated instance.

Re-read current selection when a menu action is clicked: rejected because context
menus can outlive the selection that originally created them.

## Consequences

The independent feature classes can be exercised without constructing Uno controls.
MainPage still directly uses services for unrelated Repository Files preview/editor
scenarios, which are outside this extraction.

Normal repository read cancellation is session-driven; an already started Git GC is
not forcibly cancelled. A successful GC is distinguishable from its post-statistics
or targeted-refresh failures.

There is no product-intent change. Future feature operations must capture immutable
requests and use the existing repository context rather than own a parallel mutable
selection or mutation gate.
