# IDD-0037.spec-recent-repositories-start-screen

## Intent

Стартовый экран CSharpGit должен оставаться удобным при большой истории локальных
репозиториев: recent repositories можно быстро найти, важные репозитории можно
закрепить и расположить вручную, а empty state и список recent repositories не
перекрывают друг друга.

## Behavior

- При отсутствии открытого repository start screen имеет явные состояния:
  обычный empty state при пустой history и repository launcher при непустой.
- Repository launcher избегает повторяющихся заголовков: page title —
  `Repositories`, группы называются `Pinned` и `Recent`, а search field
  использует короткий placeholder `Search by name or path…`. Отдельный
  поясняющий subtitle над search не показывается.
- Смысл start-screen элементов не определяется их индексом в
  `RootLayout.Children`; empty state, recent host и application menu имеют
  явные XAML hosts/names.
- Хранится до 1000 незакреплённых recent repositories и любое количество
  закреплённых.
- Pinned repositories всегда отображаются отдельной секцией выше обычных recent
  repositories.
- Новый pin добавляется в конец pinned group. Повторное открытие repository
  обновляет recent metadata, но не меняет пользовательский pinned order.
- Unpin возвращает repository в обычную recent history по `LastOpenedUtc`; при
  переполнении удаляется самый старый unpinned repository.
- Пользователь может менять pinned order drag-and-drop и командами
  `Move earlier` / `Move later`. При активном search reorder отключён.
- Search фильтрует уже загруженные элементы немедленно и case-insensitive по
  display name, path и last branch. Search не выполняет Git, filesystem,
  network или image-cache operations.
- Если search не дал результатов, search field остаётся доступным и показывается
  отдельное состояние `No repositories match your search.`.
- `Remove from recent` удаляет pinned и unpinned repository одинаково.
  `Remove missing` повторно проверяет filesystem перед удалением кандидата.
- Отсутствующий repository остаётся в своём пользовательском pinned order и
  визуально помечается `Folder not found`.
- Repository preview/icon и one/two-column `VariableSizedWrapGrid` layout из
  IDD-0016 сохраняются.
- Compact и wide/preview repository tiles используют одну информационную
  иерархию: display name, отдельную строку path и отдельную metadata-область с
  branch + last opened.
- Pin и Remove/X расположены рядом как компактная action group в правом верхнем
  углу текстовой области плитки, но без общей фоновой capsule/рамки. Они не
  перекрывают path, metadata или preview.
- Обе action buttons используют одинаковую семантическую styling policy для
  compact и wide/preview tiles; Pin остаётся заметным и в pinned, и в unpinned
  state, а каждая кнопка сохраняет собственные hover, pressed и keyboard-focus
  states.
- Длинная branch metadata может занимать до двух строк с trimming после
  приоритетного показа начала branch; path при этом остаётся самостоятельной
  строкой и не конкурирует с branch за одну строку.

## Durable Architecture And Constraints

- Persisted recent model содержит `IsPinned` и nullable `PinnedOrder`;
  legacy JSON без этих свойств остаётся совместимым.
- `JsonAppSettingsService` централизованно нормализует path deduplication,
  pinned order и лимит unpinned history. После mutation committed state остаётся
  нормализованным.
- Pinned order и `LastOpenedUtc` независимы.
- Presentation строит projection persisted state на pinned/recent + search, но
  не редактирует JSON напрямую.
- Existing `RecentRepositoryItem` переиспользуется при pin/unpin/reorder и
  metadata updates. Простое изменение settings не должно повторно выполнять
  `Directory.Exists` для всех элементов или инвалидировать repository-image
  cache.
- Availability является snapshot item state; явный `Remove missing` имеет
  право повторно проверить filesystem.
- Action buttons start screen участвуют в обычном layout flow и должны
  переноситься на узком окне вместо перекрытия repository tiles.
- Repository tile action buttons имеют shared semantic application-level
  style; варианты compact и preview не вводят независимые competing visual
  implementations или общий декоративный container вокруг action group.
- Tile text layout резервирует action area в верхней строке, а path и metadata
  начинаются ниже capsule, поэтому увеличение длины текста не создаёт overlap.

## Acceptance Criteria

- Empty state больше не перекрывает Recent repositories.
- До 1000 unpinned repositories сохраняются независимо от pinned repositories.
- Pin/unpin и manual pinned order переживают restart.
- Search по name/path/branch обновляет обе секции без I/O и сохраняет их порядок.
- Drag-and-drop reorder и `Move earlier` / `Move later` используют один
  persisted order и отключены при search.
- Preview tiles сохраняют `VariableSizedWrapGrid`, column span и image cache
  behavior.
- Pin одинаково заметен на compact и wide/preview tiles; Pin + Remove/X
  визуально расположены рядом, но не заключены в общий capsule/container.
- Path отображается отдельной строкой; branch + last opened не конкурируют с
  path и могут аккуратно занять вторую metadata-строку при длинной branch.
- Action buttons не перекрывают display name, path, metadata или preview и
  имеют заметные индивидуальные hover/pressed/focus states.
- Remove actions работают для pinned repositories, а pinned order после удаления
  остаётся плотным и детерминированным.
- Узкий start screen не содержит overlap controls.
- Repository launcher не дублирует `Recent repositories` в page title и section
  heading и не добавляет избыточный explanatory subtitle над search.

## Verification

- Unit tests покрывают лимит 1000 unpinned, pin/unpin persistence, manual order,
  legacy JSON, invalid order normalization, duplicate paths и persistence
  failure.
- Projection tests покрывают search по name/path/branch, case-insensitive
  matching и независимую сортировку pinned/recent.
- Start-screen contract tests проверяют explicit hosts, отсутствие positional
  `RootLayout.Children` assumptions, search/pin/reorder controls и сохранение
  preview layout.
- Вручную проверяются normal/pinned compact tiles и wide/preview tiles с
  короткими и длинными path/branch, включая hover, pressed и keyboard focus
  обеих action buttons.
- Проверяется, что action group без общей capsule не конфликтует с preview и
  заголовком, а metadata wrapping/trimming не увеличивает visual overload плитки.
- CI build и существующий test suite проходят.
