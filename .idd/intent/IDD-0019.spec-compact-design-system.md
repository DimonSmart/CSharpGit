# IDD-0019.spec-compact-design-system

## Intent

CSharpGit использует единый compact design system для плотности, typography,
spacing и основных presentation surfaces, чтобы рабочее пространство оставалось
компактным и согласованным без локальных дублирующих magic numbers.

## Related Specifications

- IDD-0004
- IDD-0009
- IDD-0010

## Behavior

- Общие semantic metrics задают normal density для повторяющихся UI surfaces.
- Styling выбирается по semantic role элемента, а не только по типу control:
  одинаковая semantic role использует одну shared styling policy.
- Однострочные compact TextBox выравнивают текст и placeholder по вертикальному
  центру; многострочные редакторы выравнивают содержимое по верхнему краю.
- History является специальной dense-row surface: его commit graph визуально
  продолжается между соседними строками и не воспринимается как набор
  независимых row icons.
- Shared data-row metric задаёт normal density target для History, а graph
  rendering адаптируется к фактической arranged row height.
- History, Repository Tree и diff используют compact density; формы и стартовый
  экран могут использовать более свободное внешнее пространство, не изменяя
  плотность повторяющихся рабочих строк.
- Изменения density и styling не создают незакрытые вертикальные gaps между
  соседними graph drawing surfaces.
- Текстовые колонки History имеют небольшой semantic gap, чтобы значения соседних
  колонок визуально не сливались без необходимости добавлять постоянные dividers.
- Selected History row остаётся визуально различимой независимо от keyboard focus
  frame; compact styling сохраняет platform selection, hover и pressed states.
- Повторяющиеся runtime-controls C# используют общие styles/tokens из XAML:
  typed lookup выполняется после инициализации ресурсов приложения.
- Семантические иконки основных действий согласованы между экранами, Fetch и Pull
  визуально различимы, используют сдержанный двухцветный язык и сохраняют
  динамические подписи и accessibility names.
- Technical text, не относящийся к diff, использует общий technical/monospace role;
  diff-specific styles могут наследовать этот role.

## Visual Intent

- Повторяющиеся рабочие поверхности сохраняют компактную плотность: они помещают
  много полезных Git-данных на экране, не смешивая строки, колонки и действия.
- Соседние рабочие области различаются умеренными тональными шагами; их границы
  видимы с первого взгляда, но не конкурируют с данными.
- Контролы и контейнеры используют небольшое скругление, сохраняя точный,
  инструментальный характер desktop-приложения.
- Иерархия поверхностей передаётся сдержанной слоистостью. Выраженные
  декоративные тени и карточная подача не являются основой рабочего интерфейса;
  постоянные рабочие поверхности остаются плоскими, а elevation допустим только
  для transient overlay и modal surfaces.
- В каждом контексте основное подтверждающее действие имеет умеренное визуальное
  превосходство; остальные доступные действия остаются secondary, а destructive
  действия сохраняют критическую семантику, не становясь основным акцентом.
- Двухцветные функциональные иконки остаются компактными, узнаваемыми и
  ориентированными на задачу, а не иллюстративными; они применяются к навигации
  и ключевым Git-операциям, тогда как плотные строки списков используют
  монохромные glyphs.

## Durable Architecture And Constraints

- Нормальная плотность общих controls и rows определяется design-system metrics,
  а не дублирующими числовыми константами в отдельных presentation components.
- Icon glyph data принадлежит Styles/Icons.xaml, а каждый visual parent создаёт
  собственный FontIcon; shared UIElement не используется.
- Bulk Working Tree actions и группы file version/diff/reveal buttons
  объявлены в XAML ровно один раз, без runtime-перестройки их parent controls.
- Рефакторинг presentation не меняет Git commands, destructive confirmations,
  Refresh states, default Pull strategy или keyboard/automation behavior.
- Каждый reusable application-level style/template имеет одного canonical owner.
  Порядок merged dictionaries определяет availability dependencies, но не служит
  механизмом выбора между competing production implementations одного resource key.
- Повторяющиеся controls одной semantic role используют shared metrics и styles;
  application-wide implicit style не является обязательным, если keyed semantic
  style безопаснее для dialogs, menus, flyouts или platform controls.
- Размеры, задающие intentional geometry конкретной surface (например pane,
  splitter, dialog, landing card или content/editor min/max size), могут оставаться
  локальными и не обязаны становиться global design tokens.
- History сохраняет общий compact density target, но его layout обязан
  предоставлять commit graph непрерывную drawing surface через границы строк.
- Commit graph не владеет стандартной высотой History row и строит geometry по
  фактической высоте предоставленной drawing surface.
- Compact ListView styling не должен заменять platform control template способом,
  который теряет selected, hover, pressed или focus visual states.
- Межколоночный gap History задаётся именованным semantic resource, а не
  повторяющимися локальными numeric margins.
- Подробный canonical invariant commit-graph continuity и его verification
  определены в IDD-0004; этот документ не дублирует geometry semantics.

## Non-Goals

- Фиксирование конкретного control template как обязательной реализации.
- Фиксирование текущего числового значения normal data-row height навсегда.
- Перенос каждого единичного literal layout value в global token.
- Принудительное использование одного универсального style для controls разных
  semantic roles.
- Изменение commit graph topology, branch/lane allocation или Git semantics.
- Pixel-perfect копирование другого Git client.
- Постоянные вертикальные separators между всеми History columns.

## Acceptance Criteria

- Повторяющиеся compact surfaces используют общие semantic density metrics.
- Одинаковые semantic roles используют общую shared styling policy.
- Однострочные compact TextBox вертикально центрируют текст и placeholder,
  многострочные поля сохраняют выравнивание содержимого сверху.
- Shared semantic glyphs различимы, Fetch и Pull имеют разные иконки.
- Рабочие панели сохраняют компактное, различимое представление данных с
  умеренным тональным разделением соседних поверхностей.
- Рабочие списки сохраняют compact density, а формы и start screen могут иметь
  более свободное внешнее пространство без изменения shared row metrics.
- Скругление controls и контейнеров остаётся небольшим, а визуальная глубина
  служит иерархии без выраженной декоративности; постоянные рабочие поверхности
  не используют тени.
- В контексте явно различимы умеренно выделенное primary action, secondary
  actions и destructive actions с сохранённой критической семантикой.
- Основные функциональные иконки используют согласованный сдержанный
  двухцветный язык без потери различимости и доступных имён; glyphs в плотных
  списках остаются монохромными.
- Динамические действия остаются доступны с клавиатуры, с tooltip и доступным именем.
- Stage all / Discard all / Unstage all имеют одного владельца в XAML;
  selected actions остаются в context menus.
- Original / Changed / Diff tool / Reveal присутствуют в обоих diff headers.
- Reusable application-level resource keys имеют одного canonical owner, а
  correctness не зависит от merged-dictionary override order.
- Intentional surface/layout geometry может оставаться локальной.
- History использует shared data-row density target без отдельной фиксированной
  production row-height константы.
- Commit graph остаётся визуально непрерывным при фактической высоте History row,
  отличающейся от normal density target.
- Изменение shared density metric не требует переноса того же значения в graph
  implementation.
- Message, author, date и hash визуально разделены минимальным semantic spacing.
- Выбранный commit имеет заметное selection background состояние; keyboard focus
  может добавлять рамку, но не заменяет selection highlight.

## Verification

- Проверяется единый каталог semantic icons, разница Fetch/Pull и отсутствие
  общего FontIcon instance для нескольких visual parents; в GUI проверяются
  согласованный сдержанный двухцветный характер и различимость иконок.
- XAML contract tests проверяют выравнивание одно- и многострочных compact TextBox;
  в GUI вручную проверяются placeholder, введённый текст и text scaling.
- Проверяются XAML-owning groups и contract bindings для bulk/file actions;
  selected actions тестируются через context menus.
- Windows/macOS smoke матрица покрывает glyph, light/dark themes, disabled,
  focus, tooltips, scaling и длинные динамические подписи; если нет GUI,
  соответствующие сценарии остаются явно неподтверждёнными.
- Проверяется dependency order основных design dictionaries и отсутствие competing
  application-level resource definitions между ними.
- Проверяется canonical ownership history/reference и repository-tree resources.
- Проверяется, что normal History density приходит из общего design system, а не
  из commit graph implementation.
- Проверяется непрерывность соседних graph drawing surfaces при normal и
  увеличенной фактической высоте строк.
- Проверяется, что изменения compact density не ухудшают scrolling/recycling,
  selection/hover states и поддерживаемые display scaling scenarios History.
- Проверяется наличие semantic spacing между текстовыми History columns.
- Проверяется mouse и keyboard selection: selected row сохраняет видимый accent
  background, а focus visual остаётся отдельным дополнительным состоянием.
- В GUI проверяется, что History, Repository Tree и панели действий сохраняют
  компактную плотность, различимые умеренно-тональные границы и небольшое
  скругление без доминирующих декоративных теней.
- В GUI проверяются: более свободное внешнее пространство форм и start screen не
  изменяет плотность рабочих списков; постоянные workspace surfaces не имеют
  теней; primary, secondary и destructive actions различимы; двухцветные
  иконки ограничены навигацией и ключевыми Git-операциями, а dense-row glyphs
  остаются монохромными.
