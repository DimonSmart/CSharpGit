# IDD-0028.spec-branch-folder-deletion

## Intent

Пользователь может удалить все branch leaves внутри выбранной branch folder в
Repository Tree одной подтверждённой bulk operation. Branch folder является только
presentation-группировкой имён по `/`; Git не получает отдельную folder deletion
semantics.

## Related Specifications

- IDD-0006 — refs and remotes
- IDD-0009 — desktop experience and mutation/error handling
- IDD-0012 — Repository Tree navigation and reconciliation
- IDD-0021 — single-branch deletion

## Behavior

- Каждый `BranchFolder` получает strongly typed `BranchFolderInfo` в
  `RepositoryTreeDescriptor.Value`. Metadata содержит local/remote scope, полный
  relative folder prefix и, для remote folder, exact configured remote name.
- Stable tree keys остаются identity/reconciliation mechanism и не используются как
  deletion API. Bulk deletion не парсит `RepositoryTreeNode.Key` для восстановления
  semantic information.
- Context menu local folder содержит `Delete all branches in this folder…`; remote
  folder — `Delete all remote branches in this folder…`. Root `Branches`, root
  `Remotes` и remote root bulk-delete action не получают.
- При открытии action приложение один раз рекурсивно собирает branch leaves из
  `RepositoryTreeNode.Children`. Git identity каждого leaf берётся только из
  `GitBranch.Name`; display name, key и заново вычисленный folder prefix не
  используются.
- Полученный snapshot сортируется по полному branch name через
  `OrdinalIgnoreCase` с ordinal tie-break. Один и тот же snapshot и порядок
  используются для confirmation, execution, counts и failure presentation.

## Local Folder Deletion

- До confirmation local snapshot разделяется на eligible и skipped branches.
- Current branch (`GitBranch.IsCurrent`) и branch, принадлежащая любому worktree
  (`AssociatedWorktreePath`), skipped. Если выполняются оба условия, причина —
  `current branch`. Force mode не меняет эти eligibility rules.
- Если eligible branches отсутствуют, Git mutation не запускается. Пользователь
  получает informational dialog со skipped branches и причинами.
- Иначе показывается один confirmation dialog с attempted branches, skipped
  branches, bounded scrollable list и одним выключенным по умолчанию checkbox
  `Force delete branches even if they are not fully merged`.
- Без opt-in все eligible branches удаляются через
  `IReferenceService.DeleteBranchAsync(..., BranchDeletionMode.Safe)`. После opt-in
  всем eligible branches передаётся `BranchDeletionMode.Force`.
- Safe failure не повторяется автоматически как Force. Git остаётся source of truth
  для merged/unmerged safety, reachability и фактической возможности удаления.

## Remote Folder Deletion

- Remote confirmation показывает полный snapshot remote branch names и не содержит
  Force или option удаления corresponding local branches.
- Configured remote берётся только из `BranchFolderInfo.RemoteName`.
- Для Git operation relative branch name получается удалением точного
  `RemoteName + "/"` из полного `GitBranch.Name`. Наивный `Split('/')[0]` и
  `BranchDeletionResolver` для поиска local counterpart не используются.
- Если leaf не начинается с exact configured remote prefix или relative name пусто,
  presentation state считается inconsistent. Destructive operation не запускается;
  UI показывает application error и предлагает refresh/retry. Другой remote не
  угадывается.
- Валидные branches удаляются через существующий
  `IReferenceService.DeleteRemoteBranchAsync(repository, remoteName, relativeName)`.
  Local tracking branches не изменяются.

## Mutation, Partial Success And Refresh

- Confirmed folder deletion выполняется ровно одним `_viewModel.RunMutationAsync`.
  Все individual Git calls выполняются последовательно внутри его mutation lambda;
  отдельный refresh на branch не запускается.
- Ошибка отдельной branch ловится внутри bulk loop, записывается как
  `<branch name> / Git: <message>` и не останавливает следующие branches.
- `OperationCanceledException` не становится per-branch failure и прекращает loop,
  проходя через существующую cancellation semantics.
- Операция non-transactional: успешные удаления не откатываются после последующей
  per-branch failure.
- Counts различают `total`, `skipped`, `attempted`, `success` и `failed`.
  Post-operation dialog показывается только при наличии per-branch failures.
  Полный успех attempted branches не получает отдельный success dialog, даже если
  до mutation были skipped branches.
- Если сам `RunMutationAsync`/repository refresh завершается failure, existing
  ViewModel error handling authoritative; bulk UI не показывает поверх него
  misleading success/failure summary.
- После mutation используется существующий repository-state refresh и incremental
  Repository Tree reconciliation. Surviving failed/skipped nodes остаются; folder
  исчезает только когда surviving descendant branches больше нет.

## History Scope

- Bulk loop сохраняет полные имена фактически успешно удалённых branches.
- После loop, но внутри той же mutation, history возвращается к `All references`
  ровно один раз только если `_activeReference` входит в successful set.
- Skipped, failed и не входившие в snapshot branches history scope не изменяют.

## Durable Architecture And Constraints

- Bulk folder deletion — Presentation/application orchestration существующих
  single-branch Git primitives, а не новый Git mechanism.
- `BranchFolderInfo`, snapshot planning, deterministic filtering/counting и small
  execution helper принадлежат Presentation/ViewModels layer.
- Не создаются `IBulkBranchDeletionService`, bulk Git API или второй Git execution
  mechanism.
- Semantic Git decisions остаются Git: merged safety, reachability, remote/server
  protection, permissions и authentication не вычисляются UI code.
- Deterministic structural decisions остаются code: recursive descendants, node
  kind, current/worktree eligibility, counts, exact known remote prefix и ordering.
- Existing IDD-0021 single-branch local/remote workflows и их semantics не меняются.

## UX Constraints

- Confirmation lists и failure summaries находятся в bounded scrollable container;
  dialog не растёт неограниченно для десятков или сотен branches.
- Primary confirmation button отражает attempted count, а не total descendants.
- Формулировки confirmation не обещают, что все attempted branches обязательно
  будут удалены: Git может отказать отдельным branches.

## Non-Goals

- Bulk delete через root `Branches`, root `Remotes` или remote root.
- Multi-selection или выбор отдельных branches внутри confirmation.
- Per-branch Force controls, merged-status precomputation или Safe-to-Force retry.
- Commit reachability/lost-commit preview, undo, automatic checkout или worktree
  modification/removal.
- Combined bulk remote + local deletion и поиск tracking counterparts.
- Parallel deletion, rollback, новый cancellation UI или собственная remote branch
  protection detection.

## Acceptance Criteria

- Local и remote `BranchFolder` имеют корректные scoped bulk-delete actions, а root
  nodes — нет.
- Folder metadata strongly typed и не извлекается из tree key.
- Recursive immutable snapshot основан на `GitBranch.Name`, детерминированно
  отсортирован и используется после confirmation без повторного traversal.
- Current/worktree local branches skipped до mutation; zero eligible не запускает
  mutation.
- Local mode Safe по умолчанию; Force только explicit opt-in и единый для operation.
- Remote deletion использует exact configured remote и удаляет только remote leaves.
- Per-branch failure не останавливает operation; cancellation не преобразуется в
  failure; counts используют attempted semantics.
- На confirmed operation приходится один `RunMutationAsync` и один normal refresh.
- Post-operation summary появляется только при реальных per-branch failures.
- Active history scope сбрасывается только при фактическом успешном удалении active
  reference.
- Existing single-branch deletion остается без изменения.

## Verification

- Repository Tree tests проверяют `BranchFolderInfo`, nested relative prefixes,
  configured remote name, stable keys и recursive leaf structure.
- Planning/execution tests проверяют recursive collection, full branch identity,
  deterministic ordering, local skip rules, zero eligible, exact remote prefix,
  inconsistent remote state, sequential partial success и cancellation semantics.
- Desktop contract tests проверяют scoped context actions, busy restriction,
  confirmation/Force boundary, bounded scroll, one mutation per operation, failure
  summary и отсутствие single-branch remote/local coupling в bulk workflow.
- Existing Git integration tests остаются canonical verification для Safe/Force local
  deletion, remote push-delete и branch names containing `/`.
